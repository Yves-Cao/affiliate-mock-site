# 15. ER图文字说明

版本：v0.1。状态：概念及逻辑关系已整理，待绘制和数据库评审；不是物理DDL或生产建表依据。

对应图示：[Mermaid预览](15-ER图-Mermaid预览.md)，已定逻辑基数使用ER图，未定资金关系单独标注，不补造物理Schema。

## 1. 图的目标与拆分

表达核心对象、主键、基数、金额来源和状态分离，支持从任一资金结果反查业务证据。
建议先画核心主图，再分归因、资金、风险/治理三个局部图。
主键名称沿用现有逻辑模型；未定义的物理外键、索引、删除策略和事务实现由技术评审补齐。

## 3. 关系连接与基数

| 起点 | 终点 | 基数及含义 |
| --- | --- | --- |
| 合作者 | 点击 | 一对多；点击保留当时链接和Sub ID |
| 客户 | 有效归因 | 零或一；一个客户不得同时有两个有效Affiliate归属 |
| 合作者 | 有效归因 | 一对多；IB与CPA归属隔离 |
| 客户 | 快照/资金/交易事实 | 一对多；保留来源及版本 |
| 客户 | 资格案件 | 一对多；不同资格阶段区分 |
| 资格案件 | 佣金案件及版本 | 一对多；基础CPA与独立质量服务案件分开 |
| 佣金案件 | 配置/价格/权益快照 | 每次计算引用确定版本；物理快照组织待定 |
| 佣金案件 | 结算案件 | 必须可关联；是否一对一及重开/重算建模待技术确认 |
| 结算运行 | 结算明细/处理案件 | 一对多；同一运行含成功、阻断、失败记录 |
| 来源佣金案件 | 保证金明细 | 逐案可追溯；拆行和物理基数待评审 |
| 合作者 | 资金流水/提现 | 一对多；金额变化可回放 |
| 提现 | 结算单 | 一对一逻辑单据；更正保留同一单据的版本链 |
| 结算单 | 结算单行 | 一对多；每行反查原佣金、保证金或调整 |
| 提现 | 提现分摊 | 一对多；分摊总额等于订单金额 |
| 提现 | CRM付款尝试 | 可多次尝试留痕；原付款未知时禁止盲目新增支付 |
| 风险信号/申诉 | 当前案件三元组 | 明确customer_id+commission_case_id+settlement_case_id |
| 风险案件组/集群 | 成员与证据 | 多对象关联；案件组不等于集群，不等于冻结范围 |
| 来源业务对象 | 任务/审批/执行/审计 | 通过稳定引用关联，状态互不覆盖 |

## 4. 金额和状态约束

1. 金额使用定点十进制，MVP仅USD；精度、舍入与字段类型需正式Schema确认。
2. FTD为里程碑，不因此生成可放款资金；有效FTD承接基础CPA前两阶段及其附加。
3. 基础FTD比例与有效FTD比例合计100%；质量服务在基础100%外单独计佣。
4. commission_status、settlement_status、withdrawal_status、statement_status、tax_assessment_status、guarantee_status分别保存。
5. 自动结算运行不能直接关联为“已生成用户结算单”；结算单仅在手动提现提交时创建。
6. 失败、退回、更正不删除原结算单、付款记录或资金流水；调整使用新版本和反向记录。
7. 分摊不得被两笔在途提现重复占用；并发锁定与释放必须由服务端保证。
8. 风险冻结边界不能从customer_id或partner_id级联扩大到无关佣金。

## 5. 冲突与待评审

旧数据模型以“合作者+周期+版本”描述结算单，已被接口v0.14第8A节及状态字典第14节的一对一规则替代。
SettlementCase、逐佣金保证金行、付款尝试及分摊字段仍需回填完整数据字典，不能把本表视为已冻结Schema。
旧模型的commission_case_id保证金引用不完整，绘图必须保留逐案追溯需求，具体外键由后端确认。
上下级分润属于内部讨论扩展区，暂不新增生产分润实体及金额关系。
归因更正的历史版本与“一个客户单一有效归属”要同时表达，不能据唯一约束删除历史。
