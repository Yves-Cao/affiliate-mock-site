# 18. 事件流转图文字说明

版本：v0.1。状态：文字资料已整理，待绘制及事件Schema/消费者技术评审；不声明全部事件已实现。

对应图示：[Mermaid预览](18-事件流转图-Mermaid预览.md)，包含通用流转、资金事件时点和当前案件风险申诉，未定恢复时点保留待决。

## 1. 图的目标与分类

表达每类事件由谁产生、谁消费、何时改变业务状态，以及重复、乱序、缺失和补偿如何处理。
建议主图显示“来源、接收校验、领域事务、Outbox、消费者、确认/补偿”，资金和风险另用局部图展开。
ui.*表示页面交互，domain.*表示业务结论，integration.*表示跨系统交互类别；类别前缀不等于所有现有event_type已经如此命名。
浏览器CustomEvent或页面刷新不能作为计佣、结算或付款已成功的证据。

## 2. 流转节点

| 编号 | 节点 | 责任 |
| --- | --- | --- |
| EV01 | 来源生产者 | CRM事实适配、Affiliate领域操作、批准执行器、调度任务 |
| EV02 | 来源校验与去重 | 校验身份/签名、Schema、事件ID、外部引用及版本 |
| EV03 | 领域处理器 | 按事实和状态机决定业务结果，不按到达顺序盲改 |
| EV04 | 业务记录与审计 | 保存结果、版本、原因、证据和责任人 |
| EV05 | 事件Outbox | 持久保存待投递事件与负载摘要 |
| EV06 | 消费者投递 | 按接收方裁剪字段，记录每次尝试和状态 |
| EV07 | IMC消费方 | 分析统计、消费确认；不回流控制计佣 |
| EV08 | 通知/合作者回传 | 公开结果、有限原因与下一步；内部证据禁止外发 |
| EV09 | 内部业务消费者 | 创建任务、刷新投影、后续重检；按权限与幂等执行 |
| EV10 | 补偿与人工任务 | 查询、重投、补数、冲突复核和告警 |

## 3. 主链连接

| 起点 | 终点 | 条件与结果 |
| --- | --- | --- |
| EV01 | EV02 | 收到新事实或状态变化；未知类型隔离并报错 |
| EV02 | EV03 | 格式、来源、唯一性、对象版本检查通过 |
| EV02 | 历史结果 | 同事件重复返回处理记录，不再执行业务副作用 |
| EV02 | EV10 | 摘要冲突、版本缺口、无法排序或来源无效 |
| EV03 | EV04+EV05 | 业务更新与待投递事件保持可靠一致；具体事务实现待技术评审 |
| EV05 | EV06 | 选择未确认投递，分消费者记录重试 |
| EV06 | EV07/EV08/EV09 | 按消费者契约和字段白名单投递 |
| 消费者 | 投递确认 | 持久完成后确认，不以HTTP接收替代最终处理语义 |
| 投递失败 | EV10 | 按策略重投、告警，达到上限转人工 |
| EV10 | EV02/EV03/EV06 | 补事实、重检或原事件重投；保留原事件和关联 |

## 4. 主要事件组

| 生产者/触发 | 事件名示例 | 消费者及边界 |
| --- | --- | --- |
| CRM账户同步适配 | partner_crm_sync_completed/failed、partner_kyc_status_changed | 账户投影、任务、通知；不伪造CRM事实 |
| 归因与事件健康检查 | attribution_integrity_check_completed、event_gap_detected、event_backfill_completed | 归因审计、补数任务、受影响结算检查 |
| 风险与调查 | investigation_required/concluded、cluster_suspected/confirmed/cleared | 统一任务、风险投影；集群疑似不直接确认资金处罚 |
| 信用记录 | credit_point_recorded、credit_level_changed、credit_benefit_locked | 信用及权益投影；内部积分不外发 |
| 超时冻结 | settlement_overdue_frozen、settlement_overdue_signal_created | 当前案件冻结、人工任务；携带案件三元组 |
| 风险信号复核 | settlement_overdue_signal_rejected/confirmed | 资格重算/后续任务；驳回不直接解冻 |
| 申诉 | settlement_appeal_visibility_changed、settlement_appeal_created | 当前案件入口及人工流程；不能改其他案件 |
| 每日自动结算 | settlement_run_started/completed/failed | 运行监控、逐案结果和告警；不创建提现订单 |
| 税费与保证金 | tax_assessment_calculated、guarantee_released | 资金流水、余额投影及审计；不重复释放 |
| 合作者手动提现 | withdrawal_submitted、statement_generated | 生成唯一关联结算单、审批和通知 |
| 提现批准后 | crm_payout_requested | CRM付款集成任务；请求不等于已到账 |
| CRM付款结果 | crm_payout_status_changed、withdrawal_reconciled | 提现、分摊、流水与对账分别更新 |
| 客户服务 | support_ticket_created/updated/closed | 按消息受众通知、协作回写；内部备注不通知合作者 |
| 通知投递 | notification_delivery_failed | 原通知重试；不回滚业务结果 |

## 5. 顺序、重复和缺失规则

1. event_id全局唯一，幂等键约束业务动作；同事件向不同消费者投递分别记录确认。
2. 同键同摘要复用原结果；同键不同摘要转冲突，不以新消息覆盖旧业务。
3. 按来源对象版本及业务发生时间判断先后，不以接收时间代表事实顺序。
4. 旧状态不得覆盖新状态；但迟到的更正、退回或拒付仍须走合法新事件和冲正路径。
5. 缺少关键前置事实时创建补数任务并阻断依赖的自动结算，不凭事件数量猜测资格。
6. 补数新增事件和记录，关联原事件、来源与原因；不修改历史事件负载。
7. 重放资金链路不得重复生成佣金、税费、保证金释放、余额、提现或退款。
8. CRM付款超时必须先查原付款；回调与查询并发到达仍只处理一次。

## 6. Envelope与审计锚点

图旁列event_id、event_type、schema_version、source_system/source、source_object_id、对象版本、previous_status、current_status。
时间包括occurred_at、processed_at、data_as_of；保留reason_code、rule_version、idempotency_key和trace_id。
字段命名在事件Envelope和状态字典间尚需正式Schema统一，此处列语义，不另创一套确定字段名。
敏感操作关联approval_id、task_id、execution_id及audit_id；保留请求与回执hash，不保存密钥明文。
合作方输出剔除信用分、积分流水、规则阈值、集群特征和证据全文。

## 7. 当前资料差异与待评审

事件v0.10修订后：`statement_generated`表示月度结算单生成或重算，`withdrawal_submitted`表示提现申请；二者独立发生。
源文头部的设计/实现事件数量未包含本轮新增事件核验；本图不标固定总数或全部Schema完成。
需确认正式Schema枚举、消费者版本兼容、重复保留期、确认语义、乱序缓冲策略及补偿责任。
各消费者应提供成功、重复、乱序、未知事件、失败重投和资金重放金额不变证据。
