# 13. 逻辑架构图文字说明

版本：v0.1。状态：文字资料已整理，待绘制与技术评审；组件代表职责，不代表独立微服务或已完成部署。

对应图示：[Mermaid预览](13-逻辑架构图-Mermaid预览.md)，按逻辑职责分层，并以最新DEC-032标明审批策略及权限细则待确认。

## 1. 图的目标与分层

展示页面请求如何经过授权、业务规则、任务和数据，最终连接外部系统。
可从上到下排列六层，不要求固定四层；鉴权、审计与观测作为贯穿各层的公共能力。
本图不选定数据库品牌、消息中间件、缓存、图存储或服务拆分方案。

## 2. 分层节点

| 层 | 节点 | 负责内容 |
| --- | --- | --- |
| 入口 | 合作者Web | 推广、客户、佣金、钱包、提现、账户、通知、支持和申诉 |
| 入口 | 管理端Web | 工作台、统一任务/审批、合作者与客户详情、风险、财务、配置与审计 |
| 访问 | 页面API/聚合适配 | 校验身份、对象范围、动作权限、字段可见性；提供页面一致快照 |
| 领域 | 账户与CRM同步 | 主体关联、资料版本、认证状态、冲突和清退编排 |
| 领域 | 点击与归因 | 官方路径、有效点击、CRM注册引用、最终归属锁定 |
| 领域 | 资格与佣金 | 里程碑、有效FTD、基础CPA与附加、质量服务独立案件 |
| 领域 | 风控/信用/集群 | 识别、调查、处置提案、风险档与信用等级分离 |
| 领域 | 结算与资金 | 动态结算中、税费、保证金、余额、提现、结算单、分摊及冲正 |
| 领域 | 配置与版本 | 草稿、校验、试算、审批、生效版本、回退 |
| 领域 | 服务与通知 | 工单、公开/内部消息、站内通知、邮件及合作者回传 |
| 执行 | 统一任务及审批 | 来源任务、责任人、审批节点、批准范围与执行结果 |
| 执行 | 调度与集成作业 | 每日结算、信用重算、期限检查、补数、外部结果查询和受控重试 |
| 执行 | 事件Outbox及投递 | 持久化事件、分消费者投递状态、去重和补偿 |
| 数据 | CRM事实引用/镜像 | 注册、KYC、资金、交易、欺诈来源和版本 |
| 数据 | Affiliate领域记录 | 归因、资格、佣金、风险、信用及配置快照 |
| 数据 | 资金与审计记录 | 流水、保证金、分摊、结算单版本、审批、证据引用和不可变审计 |
| 外部 | CRM/IMC/邮件等 | 分别提供事实和付款执行、分析消费、通知投递 |

## 3. 关键连接

| 起点 | 终点 | 条件与输出 |
| --- | --- | --- |
| 页面 | 访问层 | 只提交用户意图；不信任页面传入的角色或金额结论 |
| 访问层 | 领域能力 | 通过鉴权、对象范围和版本检查后处理 |
| CRM通道 | 事实引用/镜像 | 校验来源、主键、版本、数据截至时间 |
| 点击与归因 | 资格与佣金 | 已锁定客户归属及可用事实参与判断 |
| 配置与版本 | 各规则消费者 | 仅使用适用期内已批准版本，案件保留快照 |
| 风控/信用/集群 | 结算检查 | 输出案件阻断、权益或待审处置；不直接改外部事实 |
| 资格与佣金 | 结算与资金 | 有效FTD或独立质量服务案件生成后进入各自结算检查 |
| 每日调度 | 结算与资金 | 自动结算、税费及保证金释放入可提现余额 |
| 合作者提现请求 | 资金与审批 | 锁定可用分摊，生成提现及唯一结算单 |
| 批准执行器 | CRM集成作业 | 审批通过且重检通过后请求CRM打款 |
| CRM结果 | 资金与对账 | 原订单、付款尝试及分摊分别更新 |
| 领域状态变化 | Outbox/审计 | 保存事件与责任证据，防业务成功而事件丢失 |
| Outbox | IMC/通知/回传 | 各消费者独立确认，不反向覆盖原业务对象 |
| 领域异常 | 统一任务 | 创建或复用来源任务，不另建重复业务台账 |

## 4. 贯穿能力

| 能力 | 应覆盖的位置 | 必须表达的限制 |
| --- | --- | --- |
| 身份与权限 | 页面API、任务、执行器、导出、证据 | 前端隐藏不替代服务端授权 |
| 审批与隔离 | 资金和风险敏感写入 | 不同人员双角色；低敏白名单另按规则 |
| 幂等与版本 | 写请求、调度、回调、补数 | 同键同摘要复用，旧事件不覆盖新状态 |
| 审计与trace | API、领域、任务、外部调用 | 记录前后状态、原因、规则与证据引用 |
| 数据保护 | 响应、存储、日志、导出 | 最小必要、脱敏、受众过滤、受控访问 |

## 5. 失败与恢复

1. CRM事实缺失或冲突时保留待核验与任务；不编造客户或付款成功事实。
2. 集群、调查、隔离和关键缺数阻断自动结算，不取消本应计算的佣金。
3. 外部写超时先查原结果；只重试允许的失败项，不重复锁定或付款。
4. 配置回退生成新审批与生效记录；已发生账务采用重算和调整，不覆盖旧流水。
5. 审计不可用时敏感操作不得返回成功；具体事务和恢复机制待技术评审。
6. IMC或邮件失败保留投递任务，主业务结论不回滚为未发生。

## 6. 技术评审待定

逻辑组件是否合并部署、事务边界、Outbox落地、任务调度互斥、峰值容量、灾备与存储选型均待研发确认。
“配置项版本+发布包”为推荐模型，不能在图中标为已经确定的物理架构。
图中不得将内部风控画成独立外部反欺诈产品，也不得假定MVP包含机器学习模型。
