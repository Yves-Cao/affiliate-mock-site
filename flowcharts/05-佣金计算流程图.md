# 05 佣金计算流程图绘制说明

图示预览：[Mermaid佣金计算流程图](05-佣金计算流程图-Mermaid预览.md)。

版本：v0.1。状态：文字资料已整理，待绘制和业务/财务/技术评审。  
用途：说明客户行为如何转成可解释的佣金案件；与结算放行、实际付款保持边界。

## 1. 范围与前置条件

客户已有合法锁定的Affiliate归属，CRM提供认证、入金、交易等事实。起点为行为事实进入处理，终点为佣金案件及金额明细生成，或等待事实/不达标结果。仅USD。

## 2. 主节点

| 编号 | 节点 | 输出 |
| --- | --- | --- |
| C01 | 接收CRM行为事实 | 事实ID、业务时间、版本及来源引用 |
| C02 | 幂等及事实完整性检查 | 去重、乱序处理或补数任务 |
| C03 | 校验锁定归属、客户唯一性及IB隔离 | 可进入CPA资格判断的客户 |
| C04 | 按配置判断资格档及国家系数 | 资格结果、基础CPA单价及版本 |
| C05 | 判断FTD里程碑 | 记录FTD事实，不生成可放款资金 |
| C06 | 判断有效FTD | 未达成继续等待，达成进入基础CPA计算 |
| C07 | 计算基础CPA及前两环节附加 | 独立基础CPA佣金案件及明细 |
| C08 | 保存规则与权益快照 | 价格、等级、个人配置、事实引用及计算依据 |
| C09 | 进入动态结算中与风险控制 | 佣金记录存在，结算另作判断 |
| C10 | 后续质量服务确认 | 黑盒结果达成后单独生成附加案件 |
| C11 | 计佣事件、通知与审计 | 下游可靠消费；展示遵守可见性规则 |

## 3. 必须保留的计算口径

| 金额项 | 文字表达 |
| --- | --- |
| 基础CPA价格 | 资格档单价乘国家系数 |
| 基础两段 | FTD段基础比例与有效FTD段基础比例合计100% |
| 单环节附加 | 基础CPA价格乘信用附加比例与个人附加比例之和，再加两类固定金额 |
| 有效FTD时生成 | 基础CPA金额，加FTD环节附加，加有效FTD环节附加 |
| 质量服务时生成 | 基础CPA之外的质量服务环节附加，独立案件 |

比例均以完整基础CPA价格为基数，不以分段金额或上次附加金额递乘。各信用等级及每位合作者可独立配置三环节比例和固定额；生产值不在图中写死。

## 4. 连线清单

| 起点 | 终点 | 条件与结果 |
| --- | --- | --- |
| C01 | C02 | 事件或受控读取获得事实 |
| C02 | C03 | 事实可用且未重复执行 |
| C03 | C04 | 合法有效归属与隔离检查通过 |
| C04 | C05 | 取得适用资格和价格规则 |
| C05 | C06 | FTD已记录，继续等待有效FTD标准 |
| C06 | C07 | 有效FTD确认，生成一次基础案件 |
| C07 | C08 | 金额明细与依据一起保存 |
| C08 | C09 | 进入案件级结算控制 |
| C07 | C11 | 发布计佣结果及审计引用 |
| 后续客户行为 | C10 | 质量服务评估得到确认结果 |
| C10 | C08、C09、C11 | 独立附加案件，复用快照与风控流程 |

基础CPA主链在C07后直接继续，不等待C10；不要把质量服务画成基础CPA的必经前置。

## 5. 异常与修正

| 场景 | 处理 |
| --- | --- |
| 同一事实重复 | 返回已处理结果，不重复案件或佣金行 |
| 事实乱序 | 按业务时间与版本核验，不将到达顺序当行为顺序 |
| 归属缺失或不合法 | 不凭空计佣，进入归因核验或排除 |
| 有效FTD尚未满足 | 保留里程碑，不生成可放款基础CPA |
| 集群、调查、隔离或结算关键缺数 | 对已能计算的佣金继续计佣，阻断自动结算 |
| 计算本身必需事实缺失 | 不能编造金额，建立补数任务；区别于仅影响结算的缺数 |
| 价格或信用配置变化 | 使用适用规则快照；不原地污染历史案件 |
| 事后退款、拒付或欺诈 | 按批准的重算/冲正规则生成差额与反向流水，保留原账 |

## 6. 展示与数据锚点

合作者可见佣金结果、金额、状态、有限原因及下一步；质量服务不展示内部进度、差项、权重和完整规则。风险档R0-R3与合作者信用等级C0-C4分开保存。

计算证据关联客户、归属、事实、佣金案件、明细、价格/资格/信用/个人配置快照、币种、原因码及`trace_id`。幂等键和精度、舍入、版本适用时点需技术与财务评审。

## 8. 绘图核对

FTD无可放款金额；有效FTD只生成一次基础CPA；两段合计100%；质量服务在100%之外且另案；风险阻断不删除已生成佣金；计佣、入余额、付款没有混成一个状态。
