# 06 结算与资金时序图绘制说明

图示预览：[Mermaid结算与资金时序图](06-结算与资金时序图-Mermaid预览.md)，审批采用最新DEC-032及待核验动作策略，旧敏感双角色限制不作为预览授权依据。

版本：v0.1。状态：文字资料已整理，待绘制及财务/风控/技术评审。  
用途：区分佣金生成、每日自动结算、用户提现和CRM实际打款，并表达保证金、冻结、冲正与对账。

## 1. 口径与泳道

采用接口v0.14第8A节、状态字典v0.4第14节及资金专题第2A/3A节。早期“周期结算单先审批再入余额”不作为本图主链。

泳道为CRM事实、Affiliate计佣、风险与任务、每日调度/结算、资金账务、合作者、人工审批、CRM打款、支付/银行、审计对账。

## 2. 按时间顺序的主节点

| 编号 | 节点 | 结果与边界 |
| --- | --- | --- |
| F01 | CRM事实与有效FTD确认 | FTD本身仅里程碑 |
| F02 | 生成佣金案件和明细 | 基础CPA与质量服务独立 |
| F03 | 保存保证金及结算中快照 | 保证金逐佣金案件计算到期 |
| F04 | 结算中与风险检测 | 调查、隔离、集群或关键缺数阻断放行 |
| F05 | 每日凌晨调度 | 记录执行时区、计划时间和运行ID |
| F06 | 筛选与结算前检查 | 核验合作者实名及逐案门槛，失败保留原因和任务 |
| F07 | 结算计算与账务处理 | 计算税费，处理到期无风险保证金及结算明细 |
| F08 | 可提现余额入账 | `settlement_status=settled`，不表示已打款 |
| F09 | 合作者手动提现 | 纳入全部当前可用佣金及已释放保证金 |
| F10 | 订单、结算单和分摊 | 一单一结算单，阻止重复占用明细 |
| F11 | 人工审批及执行前复查 | 敏感资金动作按双角色审批要求 |
| F12 | Affiliate请求CRM打款 | 幂等请求，保留订单和结算单引用 |
| F13 | CRM与支付/银行执行 | 返回CRM编号、外部流水及回执 |
| F14 | 回执、对账与通知 | 独立更新提现、结算单、分摊及流水 |

## 3. 主要连接关系

| 起点 | 终点 | 条件/载荷 |
| --- | --- | --- |
| F01 | F02 | 有效FTD或质量服务各自确认 |
| F02 | F03、F04 | 案件与规则快照已保存 |
| F05 | F06 | 每日计划运行，重复执行不得重复入账 |
| F04 | F06 | 到期且无尚未解除的结算阻断 |
| F06 | F07 | 当前案件全部检查通过 |
| F07 | F08 | 结算明细与余额变动可追溯 |
| F08 | F09 | 用户主动申请；自动结算不替用户提现 |
| F09 | F10 | 提交时创建订单及唯一结算单 |
| F10 | F11 | 金额、账户及合规资料可审核 |
| F11 | F12 | 必要审批全部通过，执行前再次检查 |
| F12 | F13 | CRM受理请求，Affiliate不直接对银行发款 |
| F13 | F14 | 回调或查询得到可核验结果 |

F05至F08不创建提现订单、不生成结算单、不调用CRM打款。税费在结算时确认，提现不得重复扣税。

按待决事项第1A.15节“合作者实名门槛”，结算时提示完成实名，未实名不得自动或人工结算；CRM是实名事实源，不能人工绕过。

## 4. 风险冻结支线

结算中超过配置阈值，当前`customer_id + commission_case_id + settlement_case_id`进入冻结并生成`settlement_overdue`信号。阈值不写死30天，同客户其他案件、同合作者其他客户及同批次其他案件不连带冻结。

风险信号驳回前不开放申诉；驳回后按开关、窗口与次数开放。驳回、提交申诉或任务关闭均不直接入余额，必须满足解除条件并重跑F06。解除申请/执行时点与申诉窗口关系仍见VIS-RISK-Q01，不由图稿决定。

## 5. 保证金独立支线

| 起点 | 判断 | 结果 |
| --- | --- | --- |
| 逐案到期候选 | 是否存在关联未结风险或已抵扣金额 | 分离可释放与继续冻结部分 |
| 无风险可释放部分 | 尚未释放且金额有效 | 追加释放流水并进入可用余额 |
| 关联未结风险部分 | 风险未解除 | 继续冻结，保留风险关联 |
| 已释放明细进入提现 | 是否被其他订单占用 | 不允许重复纳入或重复释放 |

保证金不依赖结算单重新生成才能到期释放，不能把原始扣留流水改写为“已提现”。

## 6. 付款异常、重试与对账

- 未知或超时：查询CRM及回执事实，不能先回余额再重付。
- 确认失败或银行确认退回：仅已确认失败金额或银行已确认退回金额回余额，追加反向流水；未退回的成功金额不回退。
- 部分成功：成功部分保持已支付，未成功部分按确认结果处理。
- 重复或乱序回执：核验状态、金额及幂等键，不重复付款、退回或回退终态。
- 新提现尝试、原订单和结算单版本的关系须在技术评审定清，保留所有历史，不画“删除失败单后重建”。
- 结算单更正保留原版本及差异，正常项不重复计佣、入账或付款。

## 7. 付款后异常与冲正

CRM返回拒付、欺诈等事实后创建冲正案件；必要审批通过后，按2026-11-12用户确认的顺序处理：

1. 同一客户符合本次冲正范围的未放行佣金。
2. 同一客户关联保证金。
3. 该合作者可用于追偿的可提现余额。
4. 该合作者其他客户可用于抵扣的保证金。
5. 当前资金不足时立即登记剩余待追偿欠款（挂负）；后续佣金通过资格、Hold、风险和结算门禁后再抵欠，不等待未来佣金产生才记录欠款。

每一步仅处理剩余应追回金额，归零即停止。允许同合作者跨客户使用保证金，不跨合作者，也不扩大其他客户风险冻结。已释放入余额的保证金只在余额阶段处理一次；占用或已抵扣资金不重复使用。未放行佣金冲减应付与现金追回分开记录，记欠款不代表追偿完成。原付款流水保留，差额、反向流水和追索可回溯。完整执行约束见[资金统一契约第七节](../01-佣金结算与资金流转统一事件契约与数据指标-V1.0.md#七计算与资金守恒)。
