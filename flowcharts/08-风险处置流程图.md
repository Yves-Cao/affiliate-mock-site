## 1. 图要回答的问题

说明疑似风险怎样被发现、调查和作出结论，再经过审批与执行产生实际影响；遇到执行未知、部分成功、申诉改判及风险排除时，怎样继续处理。

范围包括重复注册、自荐或关联人、虚假或激励流量、归因冲突、设备/IP/支付集群、快速入金出金、拒付、盗卡及关键缺数。不能只画设备/IP检查。

本版分为五张子图：识别与结论、审批、执行补偿、解除与重检、超时冻结与申诉。XML使用对应五页；HTML逐图展示同一Mermaid源稿。跨图交接必须携带相同案件、任务、申请、审批、执行和限制引用。

## 4. 审批、执行及关闭

1. 风险结论与审批结果分开记录。审批拒绝只拒绝本次申请，不把既有风险改成排除，也不解除独立限制。
2. 申请人提交时，配置允许、有当前对象动作审批权限且状态门禁通过，可以显式选择自动审核。自审同事务记录`SUBMIT`和`APPROVE`，`applicant_id=approver_id`且`self_review=true`。事务失败或审计不全则整体失败。
3. 未选择自审时，申请人不得事后审批同一对象；没有其他有权审批人则保持待审并告警。自审不替代其他必要专业节点。
4. 执行未知先查询原`execution_id`及原请求，不盲目重发。成功子项保留且不重复；只重试确认符合条件的失败子项，未执行项经核验后执行。仍未知的子项继续查证。
5. 范围、动作或批准快照变化须重新预览、审批。不能通过补偿悄悄扩大批准范围。
6. 必要执行、后续核查及相关申诉处理终结后，服务端才能关闭对应任务或案件。结算资格恢复、信用恢复和风险关闭分别判断。

## 5. 解除与超时冻结边界

普通限制须满足对应恢复条件，再申请解除指定限制，经审批、受保护执行和结果核验后，重检Hold、风险调查、集群、关键缺数、CRM确权、实名及其他结算门禁。任何独立阻断仍有效，就保留其处理责任。风险排除或集群纠错不直接入钱包或打款。

超时冻结仅在当前结算案件等待时长严格大于配置阈值时触发，等于阈值不触发；对应配置版本按当前业务规则保留。冻结对象是`customer_id + commission_case_id + settlement_case_id`，不扩至其他案件、客户、合作者或整批。

信号待处理、调查或待审批期间，申诉入口隐藏，接口也拒绝创建。拟驳回建议须审批及执行生效，才能按开关、窗口、次数重新判断资格。**申请被驳回**不能当作**信号驳回生效**。

成功新建申诉才按当前结算案件累计一次，重复请求返回原申诉，不新增次数。补证保持原申诉ID，不重置窗口。维持原决定保留原有效限制；改判先分类影响，涉及解除须先过图4门禁，其他必要动作再进入审批及执行，不直接解冻、冲正或付款。

`VIS-RISK-Q01`仍待联合确认：超时派生冻结的解除，能否在申诉窗口内启动，以及申请、审批、执行与申诉并发时点。图4/5明确停在待决节点，不借普通解除或改判分支绕过。

`settled`是入钱包，提现`paid`才表示对应支付结果；信号关闭不表示已支付。

## 6. 异常及审计

| 异常 | 处理 |
| --- | --- |
| 缺数、冲突或等待外部事实 | 保留已有计佣，阻断受影响自动结算，补数后重评 |
| SLA超时 | 告警升级，不能自动审批、判申诉结论、解冻或关闭 |
| 预览过期、源版本变化 | 重新预览并重审 |
| 执行失败、部分成功或未知 | 分项记录、查证、补偿与结果核验闭环 |
| 重检未通过 | 保留其余阻断，事实变化后再次重检 |
| 申诉补证、维持或改判 | 独立申诉流程，所有资金动作回到必要审批及执行 |

保留来源事件、三元组、限制ID、任务/审批/执行/申诉ID、规则配置版本、前后状态、证据、原因、操作者及角色、幂等键和`trace_id`。历史事实、决定及流水保留，更正通过关联案件留痕。
