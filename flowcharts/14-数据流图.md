# 14. 数据流图文字说明

版本：v0.1。状态：文字资料已整理，待绘制与安全、CRM、财务、合规评审；不代表已获生产数据访问授权。

对应图示：[Mermaid预览](14-数据流图-Mermaid预览.md)，分开注册认证归因与资金风险输出，保留信任边界和待核验通道。

## 1. 范围与绘图方式

本图展示个人信息、认证、归因、资金、风险数据经过哪些处理和存储，以及跨越哪些信任边界。
建议分一张总图和五类数据的局部图；每条线标数据最小集、用途、方向和授权方式。
源数据、处理过程、存储及外部接收方要用不同形状，不能把系统连接误画成任意数据共享。

## 2. 信任区域

| 区域 | 包含内容 | 边界要求 |
| --- | --- | --- |
| DF01 公网客户端 | 合作者、推广客户浏览器 | 不可信输入；不持有服务间密钥，不直连数据库 |
| DF02 Affiliate服务端 | 页面API、规则、任务、审批与执行 | 每次按身份、对象、动作、条件及字段鉴权 |
| DF03 Affiliate受控数据区 | 事实引用、领域记录、资金流水、证据、审计 | 分类存储、最小权限、保留和查询审计 |
| DF04 CRM域 | 账户、KYC、注册、资金交易事实及付款对接 | 获批表/视图或受控接口；不任意改写原始事实 |
| DF05 外部消费域 | IMC、邮件、合作者回传 | 目的限定、字段裁剪、签名与消费确认 |
| DF06 员工工作区 | 管理端及获批导出 | 岗位范围、敏感揭示、下载审计和失权撤销 |

## 3. 数据分类与存储节点

| 数据 | 来源 | Affiliate必要保存 | 默认展示/输出 |
| --- | --- | --- | --- |
| 合作者个人信息 | CRM | crm_subject_id、资料版本、必要镜像和同步摘要 | 邮箱手机掩码；仅本人或授权岗位 |
| KYC/KYB | CRM | 认证引用、状态、发起/完成时间、审计 | 只显示状态与下一步；不散发证件全文 |
| 注册归因 | 官方点击及CRM注册事实 | click_id、link_id、registration_id、customer_id、UTM、活动、Sub ID、自定义参数及锁定版本 | 合作者仅看本人客户和公开归属结果 |
| 资金/交易 | CRM及其支付执行通道 | 外部引用、业务时间、金额、币种、状态、版本 | 本人范围金额与状态；账户信息脱敏 |
| 风控证据 | 点击、CRM欺诈引用、规则、人工调查 | 证据引用、hash、特征、命中版本、处置记录 | 内部受控；合作者只见有限原因 |
| 资金结果 | Affiliate | 佣金、税费、保证金、余额、提现、结算单、分摊与调整 | 本人范围可追溯资金结果 |
| 审计 | Affiliate授权动作 | 操作者、对象、版本、前后摘要、原因与trace | 审计岗位可查；业务人员不可改 |

## 4. 核心数据连接

| 起点 | 处理 | 终点 | 条件/结果 |
| --- | --- | --- | --- |
| 浏览器推广参数 | 官方路径校验、点击登记 | Affiliate点击记录 | 原始与有效点击分离，不信任伪造身份 |
| 浏览器注册 | CRM注册保存 | CRM注册事实 | 归因参数与注册、客户关联 |
| CRM获批表/视图 | 主键、版本、新鲜度校验 | 事实镜像/引用 | 保存来源和读取时间，冲突转任务 |
| CRM KYC状态 | 认证同步 | 账户/资格门禁 | 本地不执行认证，也不伪造通过 |
| 注册事实及点击 | 归属锁定 | Attribution | IB排除和规则版本留痕 |
| CRM资金交易及归属 | 资格与计佣 | CommissionCase | 锁定价格、权益、规则和事实版本 |
| 内部证据 | 风险识别与调查 | 风险/任务/审批记录 | 证据受众与资金动作分离 |
| 案件及结算检查 | 每日自动结算 | 余额/税费/保证金流水 | 不生成提现或结算单 |
| 手动提现及账户引用 | 授权、锁定和审批 | WithdrawalOrder与Statement | 一对一；分摊引用不可重复占用 |
| 已批准提现 | CRM付款请求 | CRM及支付通道 | 带订单、结算单、净额、账户引用和幂等键 |
| CRM回执/查询 | 验签、查重、对账 | 分摊、提现和反向流水 | 结果未知先查，不自动记成功或退款 |
| 业务事件 | 最小字段投影 | IMC/通知/回传 | 各受众独立Schema和投递日志 |
| 管理端导出申请 | 范围交集、审批、快照 | 导出文件 | 下载再鉴权、过期、记录审计 |
| Affiliate业务摘要 | 待批准回传处理 | CRM | CRM展示与合规用途、最小字段尚待评审 |

## 5. 跨边界控制

1. 服务端到CRM数据库连接使用专用授权，读取与受控写入分别确认；不把数据库账号发给浏览器。
2. IP、设备标识默认hash或Token；必要原文进入额外授权的证据区。
3. 密码、会话Token、签名密钥不进入业务日志、事件、导出或截图。
4. 合作者响应剔除内部信用分、积分流水、权重、阈值、集群边和证据全文。
5. 工单公开回复与内部备注按受众分流；专业任务结论不直接复制为公开回复。
6. 附件完成扫描后才能被业务引用；访问内容时重新鉴权并审计。
7. 删除和更正请求需结合资金、审计及反欺诈保留义务，不能级联破坏账务追溯。

## 6. 异常与恢复

| 异常 | 处理去向 | 不允许发生 |
| --- | --- | --- |
| 关键事实缺失或过期 | 补数/人工任务，阻断依赖结算 | 用空值或演示数据替代真实事实 |
| 重复或旧版本数据 | 去重、版本比较及历史保留 | 重复计钱或旧状态覆盖新状态 |
| 回传/邮件失败 | 原投递重试与告警 | 以通知失败否认原业务已完成 |
| 导出权限撤销 | 拒绝下载并记录 | 因文件已生成就继续开放 |
| 数据泄露线索 | 受控事件、止血、合规处理 | 把敏感样例扩散到普通工单或日志 |

## 7. 待确认与绘图验收

CRM字段视图、SSO协议、数据保留期、跨境或第三方共享依据、导出有效期生产值待专业签核。
不得把参考值写成生产约束，也不得仅因数据库可直连就省略信任边界。
每条数据线应能回答“为什么需要、谁能看、保存什么、失败去哪”。
