# 16. 数据血缘图文字说明

版本：v0.1。状态：文字资料已整理，待绘制及数据、财务、风控评审；不声称已有生产级血缘平台。

对应图示：[Mermaid预览](16-数据血缘图-Mermaid预览.md)，包含事实到结果及更正重算追溯；资格事实/结论分工和SQL级血缘仍待核验。

## 1. 图的目标

让评审人员从页面金额、归属、风险限制或报表数字，反向找到CRM事实、Affiliate计算版本、人工决策和审计。
本图强调“结果由什么推导”，与第14份数据流图的传输和信任边界不同。
建议从上到下依次画事实层、标准化层、业务结论层、资金/风险处置层、展示输出层，旁置版本和审计。

## 4. 必须能反查的结果

| 评审问题 | 反查路径 |
| --- | --- |
| 为什么这个客户属于该合作者 | 客户归属结果、锁定规则、CRM注册原参数、原点击 |
| 为什么有这笔佣金 | 佣金版本、资格结果、CRM到账及交易、价格权益快照 |
| 为什么尚不可提现 | 当前结算案件、各阻断原因、风险/缺数/期限与生效配置 |
| 为什么某笔保证金释放 | 保证金来源佣金、逐案到期、无风险重检及释放流水 |
| 为什么提现净额如此 | 提现分摊、佣金/保证金明细、税费费用、结算单版本 |
| 是否实际付过款 | CRM请求与付款编号、外部交易回执、分摊及对账 |
| 为什么信用等级变化 | 已确认来源事件、积分流水、权重版本、系统或人工覆盖记录 |
| 报表与页面为何不同 | 指标定义、数据截至时间、过滤范围、聚合粒度与刷新版本 |

## 5. 重算、更正与补偿血缘

1. CRM事实更正保留原引用和新版本；下游标记受影响资格、佣金、结算与报表。
2. 重算产生新计算版本及差额，不覆盖原佣金、原结算单和已付款事实。
3. 已支付后的拒付或欺诈确认进入冲正追索，链接原付款与后续抵扣/负余额记录。
4. 事件补数新增事件和补偿任务，保留原事件及补数原因；不能仅补页面显示。
5. 冻结或申诉变化只改变相应对象结论，不能倒推CRM原始交易已改变。
6. 结算超时冻结记录三元组；合作者、国家、Sub ID和批次只是可追溯的上下文或聚合维度。
7. 页面“结算中”是聚合文案，不代替底层计算、结算、提现与保证金状态。

## 6. 关联字段与边界

所有关键结果至少能关联业务对象ID、来源事实引用、业务时间、数据截至时间、计算/规则版本及trace_id。
事件保留event_id及source_object_id；审批保留approval_id与批准版本；资金保留外部交易与分摊引用。
精确字段名以各契约为准，不能用“同一个trace”代替领域主键和多版本关系。
合作者可反查公开结果和有限原因，内部完整证据的访问仍受字段与对象权限限制。
IMC指标不作为资格或佣金结果的上游依据；CRM回传摘要不反向覆盖Affiliate原结论。

## 7. 待评审与绘图验收

报表SQL逐字段血缘、CRM实际表/视图及版本、质量服务来源、存量数据迁移范围待责任团队核验。
CRM是否需要Affiliate结果展示与合规引用，按该议题单独确认，不能把双向线画成全量同步。
每个结果至少有一条可追溯上游链；更正与冲正要保留旧新版本两条分支。
