# 02 当前态与目标态服务蓝图绘制说明

版本：v0.1。状态：文字资料已整理，待绘制和评审。  
用途：把合作者及客户接触的服务，与后台岗位、系统处理和数据依赖对应起来。当前态缺少完整线上证据，不据原型推定已有生产流程。

已有[当前态与目标态Mermaid预览](02-当前态与目标态服务蓝图-Mermaid预览.md)，包含两张图、完整泳道对照及异常交接；按最新需求补充阶段化开链和FTD、有效FTD、质量服务三环节。

## 1. 图要回答的问题

用户在每个阶段做什么、看到什么？哪些工作由CRM、Affiliate或人工岗位承担？现有证据覆盖哪里，目标方案还依赖什么？

## 2. 蓝图的两张视图

建议分别绘制“当前证据视图”和“目标服务视图”，使用相同阶段列，便于对比。

| 阶段列 | 服务范围 |
| --- | --- |
| B01 入驻 | 合作者账户、资料、合作计划审核 |
| B02 推广 | 官方推广链接、素材、二级渠道标识 |
| B03 注册归因 | 客户点击、CRM注册、最终归属 |
| B04 行为与计佣 | 认证、入金、交易、客户资格、佣金 |
| B05 风险与结算 | 结算中、调查、冻结、保证金、余额 |
| B06 提现与支持 | 人工审批、CRM打款、通知、申诉、工单 |

## 3. 当前态必须如实呈现

| 证据类别 | 目前可以表达的内容 | 不得推定的内容 |
| --- | --- | --- |
| 业务背景 | 资料记载已有IB体系，CPA项目处于研发准备与内部评审 | IB实际运营效率或具体人工步骤 |
| 文档 | PRD、领域规则、页面与接口设计已形成多个专题 | 文档存在即全部签核或冻结 |
| 管理端Mock | 风险工作台、任务队列、客户服务等有专项本地证据 | 全系统完整验收、真实HTTP或生产通过 |
| 用户端Mock | 有页面与契约资料，部分全量API驱动证据仍待回收 | 客户注册至银行付款已经全链路打通 |
| CRM | 已明确事实源和直连方向，注册归因能力需核验补齐 | 表/视图、字段时效、回传与打款能力均已交付 |
| 人工岗位 | 目标责任已定义 | 当前真实编制、交接习惯、SLA实测值 |

当前证据视图中的缺项直接标“待核实”；不补写用户情绪、真实耗时、线下表格或未知人工操作。

## 4. 目标服务视图泳道

| 泳道 | 六阶段对应内容 |
| --- | --- |
| 合作者可见动作 | 入驻与补件；获取链接；看客户；看收益；看结算原因；提现、申诉或工单 |
| 被推荐客户动作 | 访问官方链接；CRM注册；去CRM完成认证；入金交易 |
| 前台触点 | 合作者端账户、推广、客户、收益、钱包、提现、结算单、消息和支持 |
| 人工服务 | 运营处理入驻和一般支持；风控调查复核；财务审核提现与差异 |
| Affiliate后台 | 归因锁定、资格计佣、风险识别、任务审批、每日自动结算和账务 |
| 外部支持 | CRM账户与事实、CRM打款、支付/银行、IMC、邮件 |
| 数据与证据 | 事实版本、规则快照、案件ID、资金流水、回执、审计 |

## 5. 阶段关系与交接

| 起点 | 终点 | 交接条件及结果 |
| --- | --- | --- |
| B01 | B02 | 合作计划状态允许推广；CRM认证状态独立保留 |
| B02 | B03 | 链接有效，点击与注册可关联 |
| B03 | B04 | 最终归属锁定；CRM行为事实持续提供 |
| B04 | B05 | 有效FTD/质量服务分别生成佣金案件 |
| B05 | B06 | 每日自动结算已形成可提现余额，用户主动提现 |
| 人工调查 | B05 | 结论、必要审批与执行条件齐备后重检 |
| 一般支持 | 风险/财务任务 | 达到领域受理条件才转交，保留原工单引用 |
| CRM回执 | B06 | 分别更新提现、结算单及分摊，通知合作者 |

## 6. 服务失败与恢复

| 失败点 | 合作者可见结果 | 后台处理与恢复 |
| --- | --- | --- |
| CRM同步延迟 | 待同步或待核验 | 补数任务，按事实版本重新处理 |
| 归因冲突 | 受限说明与处理路径 | 人工核验，不覆盖原始注册数据 |
| 集群或调查 | 佣金仍记录，结算受限 | 风控任务、复核、重跑结算检查 |
| 合作者未实名 | 结算时提示完成实名 | 去CRM完成并同步事实，未实名不允许自动或人工结算 |
| 结算超时冻结 | 当前案件冻结；驳回信号前无申诉入口 | 员工核验，驳回后按开关/窗口/次数处理申诉 |
| 提现驳回 | 原因与可执行下一步 | 保存审批，按状态释放或处理占用 |
| CRM付款未知 | 处理中或超时原因 | 查询确认，不重复付款、不先行退款 |
| 确认失败或退回 | 原订单与退回记录可追溯 | 仅对已确认失败金额或银行已确认退回金额作反向流水 |

## 8. 绘图核对

- 当前态与目标态视觉上分开。
- 客户认证触点指向CRM。
- 用户可见信息与内部风险证据有可见性分隔。
- 每次人工交接都可回指案件或任务，而非口头交接。
- 失败有明确受理岗位、状态和恢复入口。
