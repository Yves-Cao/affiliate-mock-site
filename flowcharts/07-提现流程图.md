# 07 提现流程图绘制说明

图示预览：[Mermaid提现流程图](07-提现流程图-Mermaid预览.md)，审批按[角色权限与审批契约](../契约/14-角色权限与审批契约-v1.0.md)执行；旧导出图仅用于追溯。

版本：v0.1。状态：文字资料已整理，待绘制及财务/CRM/技术评审。  
用途：说明用户手动提交提现后，系统如何防重复占用、逐笔核验和审批、请求CRM打款、核验失败与退回，并保留完整审计。

## 1. 范围与前置条件

资金已经完成结算并进入可提现余额，或保证金已释放且可提现。合作者使用CRM账户，收款资料、税务资料、KYC/KYB状态分别核验；税务资料完整不等于税费已计算。MVP仅USD，提现逐笔财务核验。

实名门槛已前移到结算阶段：未实名不得自动或人工结算，不能画成只到首次提现才检查；提现执行前仍复查当前账户及合规状态。依据为待决事项第1A.15节“合作者实名门槛”。

## 2. 泳道与节点

| 编号 | 泳道 | 节点 |
| --- | --- | --- |
| W01 | 合作者 | 查看可提现收益、已释放保证金、费用及收款账户 |
| W02 | 合作者 | 手动提交提现 |
| W03 | Affiliate | 校验当前身份、资源归属、资料状态及可用金额 |
| W04 | Affiliate账务 | 按申请金额执行FIFO分摊，防重复占用 |
| W05 | Affiliate | 创建提现订单并保存分摊快照，不生成月单 |
| W06 | 财务/审批服务 | 逐笔核验金额、账户、风险与合规条件；普通审批或提交时授权自动审核 |
| W07 | Affiliate | 审批通过后的执行前复查与分摊锁定 |
| W08 | Affiliate/CRM | 幂等打款请求，记录CRM受理编号 |
| W09 | CRM/支付银行 | 实际付款及结果回传 |
| W10 | Affiliate | 回执验真、去重、金额和状态核验 |
| W11 | 账务/财务 | 更新订单、分摊、反向流水及对账 |
| W12 | 合作者/通知 | 查询结果、原结算单和后续处理路径 |

## 3. 正常连接

| 起点 | 终点 | 条件/结果 |
| --- | --- | --- |
| W01 | W02 | 合作者主动确认提交 |
| W02 | W03 | 服务端鉴权及请求幂等核验 |
| W03 | W04 | 金额、账户及资料满足申请条件 |
| W04 | W05 | 同明细不能被并发订单重复纳入 |
| W05 | W06 | 订单引用分摊明细；普通路径进入待审核，授权自审与提交同事务落审计 |
| W06 | W07 | 所有必要审批节点通过 |
| W07 | W08 | 当前账户、风险、资金占用再次检查通过 |
| W08 | W09 | CRM受理打款请求 |
| W09 | W10 | 回调或主动查询获得结果 |
| W10 | W11 | 回执已验证且业务结果可确定 |
| W11 | W12 | 结果、余额与时间线一致，保留通知和审计 |

申请阶段需要防并发重复纳入；审批后需要锁定并复查。具体预占/锁定的事务时点和失败释放边界需技术评审，图中不能只在付款后才做防重复处理。

## 4. 审核与取消分支

| 节点 | 分支 | 处理 |
| --- | --- | --- |
| W03 | 无余额、账户不合法或关键资料未满足 | 不提交付款，返回有限原因与处理入口 |
| W06 | 驳回 | 保存审批人与原因，按可执行状态处理占用 |
| W06 | 补充资料或需调查 | 保留申请与任务，不默认审核通过 |
| W07 | 新风险或账户变更 | 阻断执行并创建复核任务，不沿用失效结果付款 |
| 允许取消的阶段 | 合作者取消 | 服务端校验状态；保存取消审计及占用处理 |
| 已处理中或已支付 | 取消请求 | 不把界面取消当作银行撤回；需核验CRM能力 |

自动审核须由申请人在提交时选择，且配置允许、具备当前对象审批权限、状态门禁通过；同事务写`SUBMIT`、`APPROVE`及`self_review=true`。未选自审由其他有权人审批，所有路径均须通过支付前复查。

## 5. CRM回执分支

| CRM结果 | 资金处理 | 下一步 |
| --- | --- | --- |
| 处理中 | 保持处理中，保留请求与分摊 | 等待回调或查询 |
| 全额成功 | 成功分摊记已支付，不再占可用余额 | 对账及通知 |
| 确认失败 | 只将确认失败金额退回可用余额 | 反向流水，按授权重新尝试 |
| 部分成功 | 已成功部分不退；仅确认未成功部分退回 | 逐分摊核验并保留部分成功订单 |
| 银行确认退回 | 记录原付款成功及后续退回事实 | 反向流水和对账，不覆盖原回执 |
| 超时或未知 | 不推定失败，不先退钱或重复付款 | 向CRM查询、超时任务和人工核验 |
| 重复/乱序/金额冲突 | 不直接覆盖终态或再次变动余额 | 幂等核验，冲突进入差异任务 |

渠道是否支持部分成功以及分摊粒度需CRM和财务确认，图中标为必须覆盖的异常设计，不声称生产渠道已具备。

## 6. 订单、结算单和尝试边界

`WithdrawalOrder`通过`WithdrawalAllocation`引用一张或多张月度结算单的可提现明细，或引用等价的可用余额分摊。月度结算单由自然月任务生成，提现提交不生成结算单。

提现失败、超时或退回不删除原订单、原结算单或原回执。更正保留版本，重新打款保留新尝试和原关联；是否使用新订单及结算单新版本的完整关系仍需技术评审，不在此决定。

## 7. 数据与审计锚点

至少关联提现ID、结算单ID、合作者ID、佣金/保证金分摊、币种、金额、费用、净额、收款账户引用、申请/审批/执行时间、CRM付款ID、外部流水、回执摘要、重试次数、对账状态、幂等键、原因码和`trace_id`。

`withdrawal_status`、`statement_status`、结算状态及保证金可提现派生状态独立；`settled`是入钱包，`paid`是已打款，不能互换。提现不重复扣除结算阶段已计算的税费。
