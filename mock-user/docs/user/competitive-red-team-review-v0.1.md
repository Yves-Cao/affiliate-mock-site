# Affiliate用户端竞争红队评审记录

版本：v0.1  
日期：2026-11-10  
状态：Active。本文保存2026-11-10会话评审结论，用于后续产品决策和Mock优化；不把竞品未实测功能写成事实。

## 1. 评审边界

1. 评审对象为当前用户端静态Mock与当前用户端相关PRD口径。
2. 对照对象为成熟Affiliate/CPA平台的通用公开能力标准，不以Exness内部系统实测结果作为依据。
3. 本评审是红队视角，优先找承重假设和竞争劣势；不替代正式竞品调研、用户访谈或生产验收。

## 2. 总结论

当前原型的核心竞争力在风控、资金状态机和业务闭环覆盖，而不是合作方增长体验。与成熟平台相比，主要弱点依次为：

1. 合作方入驻与激活摩擦高。
2. 收益、保证金、结算与提现的可预期性解释不足。
3. 素材库更像合规仓库，尚未形成转化引擎。
4. 开放API、点击明细、批量操作和自动化生态弱于成熟平台常见能力。
5. 全人工审核与重状态机的运营承载能力待验证。

用户端已有21个路由，覆盖面较宽；但“页面覆盖”不等于“合作方能快速赚钱”。当前产品重心明显偏向资金安全与风控，后续需要补强合作方的首登、理解、投放和优化体验。

## 3. 头号承重假设

### 3.1 严格风控不会吓退优质合作方

钢人论证：实时硬风控、画像审核、保证金、C0观察和结算阻断可以减少欺诈与资金损失，符合立项评审中的风控诉求。

攻击：合作方若已有成熟平台可选，其感知可能是流程长、KYC跳转、链接启用有门禁、佣金规则复杂且需承担保证金。成熟平台通常先激活合作者，再基于数据逐步收紧风险；当前设计在初始阶段把高约束施加给所有合作者。

失败条件：优质合作方从注册到首个可用链接的时间明显慢于竞品，且保证金和状态门禁造成明显流失。

本周证据：8~10个目标合作方做30分钟无人引导入驻测试，记录每步停留、放弃原因、对保证金和结算周期的理解。

终止标准：入驻完成率低于40%，或超过50%测试者明确表示保证金、KYC跳转或链接门禁会阻止接入。

### 3.2 合作方能理解并信任三段CPA与资金状态

钢人论证：当前佣金、结算、提现、税费、保证金、申诉状态拆分严谨，可追溯性强，便于财务与风控复核。

攻击：对合作方而言，认知负担来自FTD、有效FTD、质量服务、动态结算、保证金、税费、结算单、提现状态和信用等级的组合。成熟平台的信任通常来自“何时能拿多少钱、多久到账”的可预期性，而不是完整状态机本身。

失败条件：合作方无法在2分钟内估算某客户带来的可提现金额和预计到账时间。

本周证据：让6个合作方只看收益、保证金、提现、结算单页面，回答三个案例的金额、可提时间和未到账原因。

终止标准：正确率低于70%，或平均回答时间超过2分钟。

### 3.3 官方素材库足以支撑高转化推广

钢人论证：官方素材保证品牌、合规、语言与尺寸一致，降低乱改素材带来的法律风险。

攻击：当前素材库仅12个素材对象，列表筛选只有全部、横幅、视频、落地页、GIF五类；不能按国家、语言、尺寸、设备、活动快速筛选，也没有素材表现对比、A/B测试、智能推荐或自建素材流程。成熟平台素材中心通常是增长引擎，不只是合规仓库。

失败条件：合作方找到合适素材超过30秒，或素材选择对转化率的影响超过流量来源本身。

本周证据：记录素材曝光、点击、注册、FTD、有效FTD；让5个合作方完成“为泰国移动流量找一个英文开户素材”的任务。

终止标准：任务平均超过30秒，或超过30%测试者要求搜索、国家、语言、尺寸、设备筛选。

### 3.4 没有开放API和点击日志也能服务主要合作方

钢人论证：MVP已有追踪器、回传配置、Sub ID、二级渠道和投递记录，可覆盖普通网站或社媒合作方。

攻击：成熟平台服务对象包括媒体采买团队、代理机构和追踪平台重度用户。此类合作方需要API拉取报表、批量创建链接、Webhook、点击明细、自动优化和自有系统对接。PRD明确将开放API、点击日志全量下载、落地页A/B测试排除在MVP外。

失败条件：目标收入中超过30%来自需要自动化集成的专业流量方。

本周证据：按预计收入把合作方分为个人社群、内容站、媒体采买、代理机构四类，访谈10个潜在合作方的工具链。

终止标准：专业流量方收入占比超过30%，或其中超过40%明确要求API、Webhook、批量链接或点击明细。

### 3.5 人工审核与重状态机能承载上线后规模

钢人论证：全人工提现审核、双角色审批、案件级风控和保证金处理能降低资金错误，适合首版谨慎上线。

攻击：MVP范围包含前后端、管理端、归因、计佣、信用、集群、保证金、税费、回传、申诉、消息、工单和清退。提现在MVP为手动提现与管理端人工审核。成熟平台已通过自动化、SLA和运营分工消化复杂度；若上线首日被审核队列、对账差异或工单淹没，合作方会立即感知不稳定。

失败条件：审核容量低于预测日单量2倍，或提现、申诉、工单P95处理时间超过24小时。

本周证据：建立30、90、365天运营压力模型，包含合作方数、客户数、佣金案件数、提现单量、申诉量、工单量和审批人数。

终止标准：关键队列出现无上限积压模型，或相同事件在不同页面金额不一致。

## 4. 相对成熟平台的劣势清单

| 维度 | 当前用户端Mock/PRD | 成熟平台常见状态 | 竞争风险 |
|---|---|---|---|
| 商业模式 | MVP仅CPA | CPA、RevShare、Hybrid、CPL或组合计划 | 只适合一类合作方，头部代理谈判空间小 |
| 素材运营 | 12个官方素材、五类标签、无搜索和A/B | 大量素材、多维筛选、表现数据、优化建议 | 增长能力弱，合作方看不到提高转化的方法 |
| 自动化生态 | 回传和追踪器已有；开放API、点击日志、A/B不进MVP | API、Webhook、批量操作、第三方生态常见 | 专业流量方接入成本高 |
| 资金与支付 | USD only、手动提现审核、保证金税费冲正复杂 | 多币种、稳定payout周期、清晰账单体验 | 跨市场拓展和资金信任吃亏 |
| 服务体系 | 工单、站内和邮件，不建完整客服平台 | 多语言客服、专属经理、实时支持常见 | 高价值合作方遇到资金问题时容易流失 |
| 本地化 | 系统语言中文、英文；素材语言更多 | 系统、素材、客服同步多语言 | 素材多语言但系统体验不同步 |
| 数据信任 | 本地合成数据；生产CRM/API/事件待核验 | 历史口碑、稳定报表与对账体系 | 第一次数据不一致即可能失去信任 |
| 优化能力 | 静态建议、报表下钻、高转化地区 | Smartlink、自动优选、素材实验、cohort分析 | 能解释数据，但不能替合作方自动赚钱 |

## 5. 当前论证充分的部分

1. 风控与资金状态机设计较深，三段结果、动态结算、保证金、信用、集群、申诉和审计均有明确对象。
2. 客户、佣金、活动、收益、提现的下钻关系较完整，适合财务和风控复盘。
3. 素材合规、语言、尺寸、平台参数和追踪参数设计较细。
4. 模拟控制台支持时间推进、违规注入、状态联动和重置，利于跨部门验收。
5. 用户端页面广度接近完整业务闭环，不是简单登录加报表。

结论不是“设计不好”，而是当前系统把成熟平台难做的后半场做得较多，还需要补强合作方最敏感的首登、理解、投放和优化体验。

## 6. 无法评估项

1. Exness内部系统真实功能、SLA、提现规则和数据延迟未实测。
2. 真实CRM、IMC、支付、KYC/KYB、欺诈库联调后的数据一致性未证明。
3. 当前合成数据不能证明真实点击归因、FTD、有效FTD和佣金准确性。
4. 管理端人工审核在真实并发下的处理能力无压力证据。
5. 目标合作方对保证金、结算周期和风控解释的接受度缺访谈数据。

## 7. 最低成本后续验证

1. 10人入驻测试：验证风控前置是否吓退优质合作方。
2. 资金理解测试：验证预计佣金、可提现时间、保证金回收是否能被理解。
3. 素材任务测试：验证国家、语言、尺寸、设备筛选的必要性。
4. 30/90/365天运营压力模型：验证人工审核与队列承载能力。
5. 端到端对账演练：验证点击、注册、FTD、有效FTD、佣金、结算和提现在相同口径下一致。

## 8. 对外表达建议

对外不应表述为“功能不输成熟平台”。更稳妥的表达是：首版以可控风控和资金确定性为优先，增长工具和开放生态按合作方分层分阶段补齐。
