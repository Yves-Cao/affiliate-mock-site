# 业务配置版本一致性修复

日期：2026-11-09  
范围：统一管理端 Mock 的业务配置模块。对应四岗位体验报告 B03，不修改产品规则正文、用户端、生产接口或数据库。

## 修复结果

| 原问题 | 当前实现 |
| --- | --- |
| 配置总览与小组读取两套生效版本 | 小组版本集合成为页面唯一事实源；总览、版本检索、小组列表、参数内容和只读抽屉引用同一版本对象 |
| 总览出现创建和回退操作 | 总览保留查看与进入配置小组；创建、复制、回退、生效仍在具体配置小组办理 |
| 生效新版本后旧版本仍可能生效 | 新版本生效时，同组原生效版本自动变为已失效；失效版本生效时间显示 `-` |
| 定时日期可填写过去时间 | 日期按 `UTC+08:00` 校验，拒绝格式错误、无效日期和不晚于服务器当前时间的值 |
| 到期版本没有执行状态变化 | 读取集合时处理到期版本；共享时钟可调用 `configRefreshScheduledVersions()` 主动推进，返回值表示是否发生状态变更 |
| 定时版本修改可能影响已生效内容 | 待生效版本锁定；取消计划转已作废并清空生效、定时时间；原生效版本继续有效 |
| 生效失败统计未包含小组失败记录 | 统计与失败筛选直接读取小组中的生效失败记录，并明确属于历史版本 |
| 配置参数摘要沿用旧固定文字 | 总览摘要从当前版本实际参数快照生成，价格档位修改后能看到同一值 |
| 国家公式金额沿用旧数组 | 国家金额直接按当前查看版本的公用基础价乘该版本国家系数计算 |
| 保存草稿逐字段写入可能部分成功 | 先复制快照、收集并校验输入，再整体替换；不修改其他版本的快照 |

## 版本与时间边界

- 生效版本始终锁定，只能复制或创建回退草稿后修改。
- 每个小组最多一个当前生效版本和一个待生效计划。
- 配置版本审核继续遵守本地 Mock 已确认例外：暂时关闭；没有修改风险、提现等业务审批。
- 复制保留独立快照；草稿填写的时间不会直接成为生效事实。计划生效时间只在“设置定时生效”操作中提交。
- 时间优先读取 `window.AFF_ADMIN_CLOCK.now()`，未提供时读取当前本地时间。配置日期显示和输入使用 `UTC+08:00`。
- 定时到期后只写一次生效审计，重复读取不会重复生效或重复记账。
- 本地规则版本和草稿仍保存在当前页面内存中；刷新页面重建既有 Mock 数据。本次未新增生产持久化能力。
- 旧 `configSeeds.versions` 历史样本未删除，但不再作为配置页面版本集合，避免与小组数据混用。

## 输入校验

本次只补已有确定约束，不新定义生产阈值：

1. 四档公用价格和国家系数必须是有限非负数。
2. FTD 与有效 FTD 基础比例分别为合法百分比，合计必须为 100%。
3. 数值输入遵守页面已有的类型、步长和范围。
4. 草稿未通过校验时，保留原草稿快照，不进入生效或定时状态。

## 验证

运行：

```bash
node --check admin-dev.js
node --check scripts/admin-config-version-domain-check.cjs
node scripts/admin-config-version-domain-check.cjs
```

定向回归 9 项通过：

1. 总览、小组及版本检索引用同一记录。
2. 总览无创建或回退按钮，失败统计来自小组记录。
3. 复制快照独立，生效后同组仅一个生效版本。
4. 锁定版本不能编辑或再次生效。
5. 草稿保存校验基础比例且整体提交。
6. 国家公式金额随选定版本快照计算。
7. 定时拒绝错误、无效及过去日期。
8. 计划到期后替换生效版本，审计只记录一次。
9. 生效版本不能被作废；撤销计划后不再自动生效。
