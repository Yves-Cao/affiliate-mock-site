版本：v0.2  
日期：2026-11-08  
状态：待评审，不作为当前 Mock、API 或正式设计规范的修改依据。  
适用范围：Affiliate 管理端配置中心、版本管理、发布包和系统配置。  
目标：先把所有可配置内容按业务责任、版本边界和操作方式分类，再调整 Mock 页面。

字段级确认底稿：本分类草案的配置项和系统配置边界已汇总到
[Affiliate管理端配置项与字段字典 v0.1](../../../Affiliate/Affiliate管理端配置项与字段字典-v0.1.md)；
本文件继续保留分类和版本模型，字段级确认以该字典为准。

## 1. 先确定配置粒度

配置中心不应把所有字段做成一张通用表，也不应把每个数字字段都拆成独立版本。建议使用以下规则：

> 能够独立进行编辑、试算、审批、生效、停用或回滚的最小业务单元，才是一个“配置项版本单元”。

因此：

- 同一规则内必须同时修改、同时审批、同时生效的字段，放在同一个配置项内。
- 可以独立启停、独立回滚或独立审批的规则，拆成不同配置项。
- 配置项内部的字段仍需逐字段展示当前值、参考范围、状态、生效条件、责任角色和审计记录。
- 已生效版本不得原地覆盖；保存修改必须生成新的待审批版本。
- 版本号建议按配置项独立递增，例如“D1-1 v1.2”“D2-1 v1.1”“动态Hold-TH v2.0”，不使用一个全局版本号覆盖所有规则。

## 2. 业务配置与系统配置的总边界

所有配置项先按是否改变业务结果分成两类：

| 分类 | 判断标准 | 是否版本控制 | 是否进入业务发布包 | 典型操作 |
|---|---|---:|---:|---|
| 业务配置 | 会改变资格判定、佣金金额、风险结论、Hold天数、保证金/税费、审批或数据权限 | 是 | 是，或进入权限/治理专属发布流程 | 编辑、试算、审批、生效、回滚 |
| 系统配置 | 只改变后台运行方式、界面偏好、通知发送或技术重试，不改变业务计算结果 | 否 | 否 | 编辑、保存、启停、审计 |

判断原则：

1. 修改后可能导致同一客户的资格、佣金、风险、Hold、保证金、税费、审批结果或数据可见范围发生变化，归入业务配置。
2. 修改后只影响页面显示、消息发送、文件过期、接口重试或维护提示，归入系统配置。
3. 无法明确判断时，默认按业务配置处理，先进入版本控制，避免绕过审批和回滚。
4. CRM提供的客户、合作方、KYC/KYB和欺诈结论是外部事实源，不属于Affiliate可编辑配置。
5. 风险事件、案件、抵扣任务、提现订单和报表结果是运行数据，不属于配置。

### 2.0 业务配置总览

业务配置区的首页为“业务配置总览”，用于查看每个配置项当前采用的版本和待生效安排。它是配置项状态的汇总入口，不替代版本列表或版本详情；系统配置不出现在此页面。

|字段|说明|
|---|---|
|配置项名称|人话化的业务配置名称|
|所属业务分类|业务奖励与资格、风控与结算、资金与财务、流程与治理、内容治理|
|当前使用版本|当前生效的唯一版本|
|当前配置参数|当前版本的摘要和“查看完整参数”入口|
|定时生效版本|已审批等待切换的版本，没有则显示“无”|
|计划生效时间|定时版本的计划时间和时区|
|当前状态|未配置、草稿、审批中、待生效、生效中、已锁定、生效失败|
|最后修改人/时间|最近一次版本或草稿变更责任人和时间|
|操作|查看参数、查看版本列表、复制、创建回退草稿|

总览与版本关系：

1. 总览的“当前使用版本”和“定时生效版本”必须引用唯一版本事实源。
2. 查看版本列表按配置项筛选该配置的全部历史版本；查看详情展示某个版本的完整参数快照、差异、影响和审计。
3. 复制任意版本只生成新的未锁定草稿，必须重新校验、试算、审批和生效。
4. 回退不直接覆盖当前生效版本，而是以指定历史版本为来源生成新的未锁定草稿。
5. 生效成功后版本自动锁定。锁定版本只能查看、复制或创建回退草稿，不能编辑、覆盖、删除或解除锁定。
6. 系统配置不进入业务配置总览、业务版本列表、业务发布包、复制、回退和定时生效。

### 2.2 系统配置范围

系统配置独立进入“系统配置”页面，不生成业务版本、不进入业务发布包：

| 系统配置分类 | 配置项 | 是否版本控制 | 保存后影响 |
|---|---|---:|---|
| 文件与导出 | 导出文件过期时间 | 否 | 控制异步文件自动过期 |
| 通知运行 | 通知摘要发送 | 否 | 控制每日待办摘要是否发送 |
| 集成运行 | 接口失败重试次数 | 否 | 控制CRM、支付、Outbox默认重试 |
| 系统运行 | 维护模式 | 否 | 控制管理端维护提示 |
| 界面偏好 | 默认页面条数 | 否 | 控制列表首次分页条数 |
| 界面偏好 | 时区显示格式 | 否 | 控制顶栏和审计时间显示 |
| 技术运行（后续） | 日志级别、健康检查频率、缓存刷新 | 否 | 只改变运行方式，不改变业务计算 |

系统配置仍需记录操作人、时间、前后值和原因，但审计记录属于系统配置审计，不生成业务版本号。

## 3. 配置中心建议结构

```text
配置中心
├── 业务奖励与资格
│   ├── 价格与佣金档
│   ├── 资格档与里程碑
│   ├── 质量服务规则
│   └── 国家与主体
├── 风控与结算规则
│   ├── D1-D10硬规则
│   ├── R0-R3风险评分
│   ├── 集群规则
│   ├── 违规规则
│   ├── 动态Hold
│   └── D+N与熔断护栏
├── 资金与财务规则
│   ├── 保证金规则
│   ├── 税费与手续费
│   ├── 结算与提现规则
│   └── 冲正、追回与抵扣顺序
├── 流程与权限规则
│   ├── 审批流与自审
│   ├── 权限与数据范围
│   ├── 数据脱敏与字段授权
│   └── 数据保留与删除
├── 版本管理
├── 版本发布
└── 系统配置
```

“版本管理”用于跨配置项查询历史版本；“版本发布”用于把多个已经完成审批的配置项版本组合成发布包；具体配置仍应从对应业务分类进入，避免先面对一张混合版本大表。

### 3.1 资格与风险判定的归属

“资格与风险判定”不应放进一个泛化的配置总表。它应拆分为：

1. 资格档与里程碑：判断客户是否达到 FTD、有效FTD、质量服务。
2. R0-R3风险评分：判断风险档和风险处置。
3. 动态Hold：根据资格、风险、国家、支付方式和信用结果计算暂扣期。
4. D1-D10硬规则：判断门禁、拦截、缺数、隔离和人工复核。

这样可以明确区分“客户是否符合奖励资格”和“系统是否允许自动结算”。

## 4. 风控与结算规则

### 4.1 D1-D10硬规则

| 配置项 | 事件/条件范围 | 版本控制 | 建议版本单元 | 处置结果 |
|---|---|---|---|---|
| D1-1 流量画像门禁 | 画像必填字段、门禁开关、首个链接启用条件 | 是 | D1-1独立版本 | 允许/阻断首个链接启用 |
| D2-1 官方路径库 | 官方域名、官方路径、适用国家、适用渠道、上下线时间 | 是 | 路径条目或路径批次版本 | 未入库目标不得生成链接 |
| D3-1 点击风险规则 | 代理、重复点击、异常来源、无效设备等确定性条件 | 是 | 每个可独立启停的规则项 | 点击无效、保留证据 |
| D4-1 关键事件缺失 | 注册、入金、交易、回传等事件缺数阈值和补数策略 | 是 | 事件类型 × 缺数策略 | 暂停自动结算或生成补数任务 |
| D5-1 案件组边界 | 集群合并、拆分、统一结论和成员资金独立原则 | 是 | 案件组识别规则版本 | 生成案件或拆分候选 |
| D6-1 新合作方基线 | 国家、渠道、合作方类型基线和低置信度标记 | 是 | 基线计划版本 | 降低自动放行置信度并提高复核优先级 |
| D7-1 调查分层 | 调查等级、链接限制、结算阻断和人工复核条件 | 是 | 调查等级规则版本 | 限制链接并阻断自动结算 |
| D8-1 解释与沟通 | 合作者可见原因码、消息模板、强制确认条件 | 是 | 原因码/模板版本 | 限定解释内容和通知方式 |
| D9-1 统一隔离队列 | 隔离来源、D+30阈值、自动放行开关、延长条件 | 是 | 隔离规则版本；D+30为后台参数 | 进入统一隔离队列，达到条件后自动放行 |
| D10-1 staging门禁 | 风控、财务、合规签核、自动审核提示和双审计 | 是 | staging门禁版本 | 阻断发布或进入人工签核 |

D1-D10属于同一“硬规则”大类，但每个可以独立启停、审批和回滚的 D 项应作为独立版本单元；不能再把全部 D 项塞进一个“硬规则 v1.0”大表。

### 4.2 R0-R3风险评分

| 配置项 | 主要字段 | 版本控制 | 建议版本单元 |
|---|---|---|---|
| 风险事件目录 | 事件名称、来源、证据要求、是否可自动确认 | 是 | 单个事件或同一事件组 |
| 风险权重与分值 | 权重、分值、正负向、有效期 | 是 | 事件评分计划 |
| R档阈值 | R0、R1、R2、R3区间和边界 | 是 | R档阈值计划 |
| R档处置映射 | Hold附加、人工复核、结算阻断、隔离动作 | 是 | R档处置计划 |
| 参考基线 | 国家、渠道、合作方类型基线和置信度 | 是 | 基线版本 |

风险事件本身的发生记录、风险案件、调查任务和命中事实属于运行数据，不进入配置版本。

### 4.3 集群与违规

| 配置项 | 主要字段 | 版本控制 | 不属于配置的内容 |
|---|---|---|---|
| 集群识别规则 | 设备、IP、支付工具、行为特征、窗口、阈值 | 是 | 实际集群成员、案件和关系图 |
| 集群结算延长 | 延长条件、延长天数、累计规则、强制人工阈值 | 是 | 某个具体案件的已延长天数 |
| 违规规则 | 违规类型、认定条件、证据要求、处理动作 | 是 | 实际违规事件和申诉案件 |

## 5. 动态Hold与结算护栏

动态Hold需要单独作为配置项，不能和普通资格规则混在一起。

| 配置项 | 主要字段 | 版本控制 | 版本单元 |
|---|---|---|---|
| 基础Hold | R0-R3基础天数、起算事件、自然日规则 | 是 | 风险档计划 |
| 国家附加 | 国家风险附加天数、国家适用范围 | 是 | 国家规则版本 |
| 支付方式附加 | 支付方式、支付风险档、附加天数 | 是 | 支付方式计划 |
| 信用调整 | 信用等级减免或增加天数 | 是 | 信用Hold计划 |
| 集群延长 | 集群触发、延长天数、累计方式、D+N关系 | 是 | 集群Hold计划 |
| D+N冻结 | 触发阈值、资金冻结、自动放行、人工复核 | 是 | D+N计划 |
| 叠加规则 | 国家、支付、信用、风险、集群是否相加及优先级 | 是 | Hold组合规则版本 |
| 释放检查 | 结算前重检、缺数、调查、案件组和支付状态 | 是 | 释放检查版本 |

计时规则、国家风险档和支付方式附加应在管理端按规则项单独查看；不能只显示一条不可解释的“动态Hold v5.2”。

## 7. 流程、权限与治理规则

| 配置项 | 主要字段 | 版本控制 | 说明 |
|---|---|---|---|
| 审批流与自审 | 节点、角色、SLA、自审开关、自动审核提示、双审计要求 | 是 | 申请人有审批权限时可选择自动审核；必须记录SUBMIT和APPROVE |
| 权限与数据范围 | 角色、页面、按钮、API、敏感字段、数据范围 | 是 | 这是权限配置，不和业务规则版本混排 |
| 数据脱敏与字段授权 | 邮箱、手机号、证件、银行卡、设备指纹的默认展示和授权时长 | 是 | 脱敏规则需审计 |
| 数据保留策略 | 点击证据、身份资料、导出文件、审计日志保留期 | 是 | 删除/匿名化任务属于运行任务 |
| 通知模板与强制确认 | 风险、调查、隔离、结算、提现和数据治理通知模板 | 视范围 | 业务原因码和强制确认模板版本化；普通通知摘要开关属于系统配置 |
| 官方路径与官方素材治理 | 官方路径、官方落地页、素材状态、国家适用范围 | 是 | 内容对象可以独立上下线和审批；不与风险规则表混排 |

## 8. 不纳入业务版本控制的系统配置

以下项目不改变佣金、资格、风险、Hold、保证金或税费业务规则，独立放在“系统配置”页面：

| 系统配置 | 当前用途 | 保存方式 |

| 通知摘要发送 | 控制每日待办摘要是否发送 | 直接保存，写系统配置审计 |
| 接口失败重试次数 | 控制CRM、支付、Outbox默认重试次数 | 直接保存，写系统配置审计 |
| 维护模式 | 控制管理端维护提示 | 直接保存，危险操作二次确认 |
| 默认页面条数 | 控制列表首次分页条数 | 直接保存，写系统配置审计 |
| 时区显示格式 | 控制顶栏和审计时间显示格式 | 直接保存，写系统配置审计 |

后续新增的日志级别、缓存刷新、健康检查频率、前端显示偏好等，也应先判断是否改变业务规则；不改变业务规则的，继续归入系统配置。

## 10. 版本与发布模型

### 10.1 配置项版本

每个配置项版本至少保留：

- 配置项ID和配置项名称。
- 配置项版本号。
- 当前状态：草稿、待审批、生效中、待生效、生效失败、已回滚。
- 完整配置快照。
- 变更摘要、影响范围和参考范围。
- 创建人、审批人、发布时间和生效时间。
- 上一版本ID、TraceId和审计记录。

### 10.2 版本发布包

发布包只引用已经生成的配置项版本，不直接复制一套新的通用字段。发布包需要展示：

- 选中的配置项和各自版本。
- 新旧值差异。
- 试算命中量、资金影响和护栏结果。
- 风控、财务、合规和系统签核状态。
- 计划生效时间、失败恢复和回滚范围。

### 10.3 复制和编辑

- 查看：打开配置项版本详情抽屉。
- 编辑：仅允许编辑未锁定草稿；对已生效/已锁定版本点击编辑时，必须改为“复制为新草稿”。
- 复制：保留原配置快照和上一版本关系，生成新的草稿版本。
- 生效：只能由发布包流程执行。
- 回滚：回滚到指定配置项版本，不能通过直接修改当前生效记录实现。

### 10.4 生效后自动锁定

- 配置项版本完成生效切换后，系统自动写入锁定时间、锁定原因（生效完成）和生效事务编号，并立即变为只读。
- 页面不提供解锁、原地编辑、覆盖当前版本或直接恢复历史版本的操作。
- 对已生效/已锁定版本的修改请求必须由后端拒绝，返回“版本已锁定，请复制为新版本后修改”，并写入审计。
- “复制”与“创建回退草稿”均生成新的未锁定版本，清空审批结果、发布时间、计划生效时间和锁定信息，但保留来源版本关系。
- 原版本在新版本生效前继续作为当前使用版本；新版本生效后，原版本仍保留为历史锁定版本。

### 14.6 字段展示的三层原则

1. **列表层**：只显示人话字段，例如“风险等级”“暂扣天数”“国家奖励系数”。
2. **详情层**：显示人话字段，并在辅助信息中显示必要的英文缩写、规则编号和操作追踪编号。
3. **审计/API层**：保留真实字段名、规则ID、版本ID、TraceId和前后值，供研发排查和审计追溯。

禁止把`D1-1`、`R3`、`Hold`、`pending_approval`、`country_coefficient`等技术表达直接作为唯一的页面标题或操作按钮。
