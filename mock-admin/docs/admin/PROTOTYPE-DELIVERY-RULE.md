# Affiliate Admin Prototype Delivery Rule

状态：Active Permanent  
生效日期：2026-11-06  
适用范围：Affiliate管理端Mock原型、页面重构、评审交付和后续迭代。  
依据：用户明确要求删除独立HTML设计稿，只保留Mock原型，并要求永久记录、后续不得再犯。

## 1. 交付定义

管理端可交付内容必须是 **Mock原型**，不是独立HTML页面。

一个合格的管理端Mock页面必须同时满足：

1. 挂在统一管理端原型入口和左侧菜单体系中。
2. 使用统一路由体系，不另建临时入口。
3. 数据来自本地Mock API、Mock fixture或统一原型数据层。
4. 页面交互会回写原型状态。
5. 有Loading、Empty、Error、Success、Disabled、Forbidden状态。
6. 有浏览器回归或最小交互验证。
7. 有操作审计或状态时间线模拟。
8. 不复制另一页面的表格和详情而不做业务差异。
9. 不以“设计稿”“静态页”“独立HTML”替代Mock交付。

## 2. 禁止事项

后续禁止：

1. 在仓库根目录新建独立管理端HTML评审页。
2. 为单个页面另建一套CSS、JS、数据文件和入口。
3. 用静态数组冒充已接入Mock，除非明确标记为本地兜底并在统一原型内使用。
4. 生成不可从统一菜单进入的隐藏页面。
5. 把视觉稿、交互稿、临时验证页当成Mock完成项。
6. 在未接入统一Mock架构前向用户交付“已完成页面”。

## 3. 正确做法

新页面或重构页面必须进入：

```text
admin-dev.html
admin-dev.js
admin-dev.css
admin-prototype-data.js
scripts/admin-prototype-check.cjs
docs/admin/
```

如需重构：

1. 先在现有原型内建立新路由或替换旧页面。
2. 保持统一菜单、统一数据层、统一抽屉、统一动作和审计体系。
3. 页面差异必须来自业务对象和工作流，不得用同一模板机械复制。
4. Mock API优先；无API时使用统一原型数据层和明确兜底策略。
5. 完成后运行管理端回归，并同步页面清单与实现记录。

## 4. 例外

只有用户明确要求“单独做设计稿”或“临时独立页面”时才可创建，且必须：

1. 放在 `.artifacts/` 或明确的临时目录。
2. 不接入根入口。
3. 不称为Mock原型。
4. 使用后删除或归档。

## 5. 违规处理

若发现独立HTML页面：

1. 立即停止对外引用。
2. 删除入口和实现文件。
3. 将有效交互逻辑迁移到统一Mock原型。
4. 在实现记录中登记原因和修复结果。
