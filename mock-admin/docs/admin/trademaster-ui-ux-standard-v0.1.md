# Affiliate Admin Mock · TradeMaster UI/UX Standard

版本：v0.1  
日期：2026-11-05  
适用范围：仅本仓库的Affiliate管理端Mock原型。  
证据来源：

1. 用户指定的TradeMaster管理端：`https://newstagadmin.gtctrader1203.top/new_admin_plus/#/members`。
2. `clone-page` quick采集：`.artifacts/trademaster-clone/screenshot.png` 与 `theme.json`。本轮直接采集到登录页、基础背景、字体和品牌结构；未记录真实客户数据。
3. 已登录工作区实测基线：`/Users/evechaqq.com/Documents/Affiliate/DESIGN-ADMIN.md`。该文件包含实际DOM、computed style、响应式和组件证据。

## 1. 布局骨架

```text
深色侧栏
└ 品牌 / 工作空间身份 / 完整产品菜单蓝图 / 版本
主区
└ 固定顶栏：面包屑、系统与本地时间、延迟、外观、语言、全局搜索、通知、权限、审计、账号
└ 已打开页签条：sticky、内部横向滚动、可关闭
└ 页面标题区：H1 + 12px描述 + 右侧主操作
└ 仪表盘：数据总结面板 → 待处理数据表 → 数据统计
└ 横向统计条
└ 筛选区 + 标签区
└ 高密度表格 + 固定选择列 / 固定操作列 + 分页
└ 页脚：产品名、版本、版权、虚构数据边界
浮动层
└ 演示面板：默认收起；抽屉或弹窗打开时自动隐藏
```

硬性规则：

1. 桌面侧栏236px；1200-1279px收为84px图标态；≤767px改为移动导航。
2. 主内容最大宽度1800px；≥1600px水平padding可增至55px。
3. `document`不得横向溢出；复杂表格只允许内部横向滚动。
4. 页面结构不加营销hero、不用蓝色用户端主题、不做低密度卡片墙。
5. 仪表盘先回答“今天处理什么、什么最危险、影响多少钱”，业务列表是承接区而不是第一认知层。
6. 左侧完整产品菜单按业务域分组：仪表盘、合作方、客户与归因、推广、佣金资金、风控合规、处理、报表、配置发布、审计治理。

## 2. Token

必须继续引用现有CSS变量，不在组件内散落hex：

| Token | 值 | 用途 |
|---|---|---|
| `--canvas` | `#F7F3ED` | 页面画布、顶栏、页签条 |
| `--surface` | `#FFFDF9` | 面板、表格行、输入 |
| `--surface-soft` | `#F2EEE7` | 表头、次级底色 |
| `--surface-hover` | `#EFE9E0` | 控件hover |
| `--text` | `#2C2924` | 主文本、主按钮底 |
| `--muted` | `#777168` | 辅助文本 |
| `--border` | `#E5DFD5` | 面板与控件边界 |
| `--accent` | `#946443` | 品牌、focus、选中 |
| `--accent-soft` | `#EFE2D4` | 选中tab/chip |
| `--accent-text` | `#71482F` | 棕金文字 |
| `--sidebar` | `#252723` | 深色侧栏 |

新增样式优先使用以上token。状态色只做状态，不做页面主色。

## 3. 字体与密度

1. 工作区字体：`Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
2. `DM Serif Display`只允许登录页大品牌文案；管理端工作区H1不使用衬线字体。
3. H1固定24px、550、行高1.3、字距0；不随视口拉大。
4. 正文13px；表格12px；辅助/状态/tab 11px；页脚9px。
5. ID、金额、时间、比例统一`font-variant-numeric: tabular-nums`。

## 3a. 控件层级

| 场景 | 尺寸 | 字号 |
|---|---:|---:|
| 页面主按钮 | 40px高 | 13px |
| 页面次按钮 | 36px高 | 13px |
| 筛选按钮 | 34px高 | 12px |
| 表格行内按钮 | 30px高 | 12px |
| 顶栏图标按钮 | 34x34px | 图标16px |
| 筛选chip | 28px高 | 12px |
| 移动端触屏目标 | ≥44px | 12-13px |

同一层级的按钮必须使用同一尺寸；按钮文字不得截断。顶栏图标按钮必须有`title`和`aria-label`。

## 4. 侧栏

1. 品牌区、工作空间身份卡、分组导航、版本信息四段固定。
2. 一级菜单12px，圆角8px，默认`--sidebar-muted`。
3. 当前与hover使用`--sidebar-active`，当前文字可用`#F0DEC5`。
4. 徽标不撑开菜单；超过99时用title/aria披露完整数量。
5. ≤1279px只保留图标态；≤767px隐藏固定侧栏，使用移动导航。

## 5. 顶栏与页签

1. 顶栏74px、`--canvas`、底边框、padding`0 38px`。
2. 左侧为面包屑；历史项`--muted`，当前项`--text`。
3. 右侧工具为34px高、圆角7px的紧凑图标按钮；hover用`--surface-hover`。
4. 系统与本地时间、延迟状态为常驻运营信息。
5. 已打开页签sticky于顶栏下方；只内部横向滚动，不得挤爆标题。

## 6. 统计与筛选

1. 列表页统计采用横向统计条：上下边框、分栏边界、20px左右留白；不做大卡片墙。
2. 数值20-24px/500-600，tabular nums；说明11px`--muted`。
3. 筛选输入和选择器高34px、圆角10px、背景`--surface`。
4. 查询为深色主按钮，重置/列设置/导出为次按钮。
5. 已选条件用chip展示，可逐项移除；筛选区不允许替代标签的必要字段名。

## 6a. 角色仪表盘

1. 顶部显示当前角色、仪表盘目标、数据源和更新时间。
2. 页面顺序固定为：数据总结面板、待处理数据表、数据统计。
3. 数据总结面板包含角色目标、4项专属概览、异常信号和快捷入口。
4. 待处理数据表紧接在总结面板下方，按角色职责、超时状态和影响金额排序；每行显示任务类型、对象ID、名称、关联对象、SLA、风险、状态、影响金额和处理按钮。
5. 数据统计位于待处理数据表之后，用于观察整体分布和影响汇总，不得抢在待处理表之前。
6. 异常信号按角色关注范围生成，可直达风险案件、集成系统、保证金维度、治理任务、通知或审计。
7. 快捷入口按角色变化，但必须复用现有4个业务路由，不新增业务页签。
8. 队列切换、筛选和完整表格保留在驾驶舱下方，不删除原有任务闭环能力。

角色重点：

| 角色 | 仪表盘重点 |
|---|---|
| 运营 | 本人任务、待处理、超时、客户申诉 |
| 风控 | 风险复核、高风险、调查SLA、阻塞金额 |
| 风控主管 | 待审批、高风险、案件组、隔离金额 |
| 财务 | 待审批、资金阻塞、待复核、影响金额 |
| 合规 | 配置审批、敏感授权、安全事件、超时 |
| 系统管理员 | 集成失败、异常系统、事件缺口、积压 |
| 审计 | 今日审计、自审、敏感导出、异常结果 |

## 6b. 左侧菜单蓝图

1. 左侧菜单是完整产品蓝图，不是当前MVP实现清单。
2. 每个菜单项必须标记`MVP`、`P1`或`P2`。
3. `MVP`入口跳转现有页签或全局能力。
4. `P1/P2`入口进入统一业务模块页面；页面顶部展示定位、对象、阶段和依赖，并可打开蓝图说明。
5. 同一底层页签允许多个业务视角别名；菜单别名不新增路由。
6. 评审时必须同时展示菜单入口数量、阶段分布和当前映射，避免把蓝图误认为已排期。
7. 母菜单是分组标题，不带箭头、不带图标；右侧只显示`MVP数量`，不得显示比例。
8. 默认只展开当前路由所在分组；点击其他分组时自动收起当前分组。
9. 子菜单必须有语义图标、缩进和左侧连接线；图标用于表达对象类型，不承担状态含义。
10. 侧栏滚动条必须隐藏，避免被误认为进度条；窄屏下子菜单只显示图标。
11. 模块页面不得使用单一“认领”模板：主操作必须按模块语义显示，例如导出合作方、生成风险复核、新建活动、认领提现、生成渠道建议、新建权限草稿。
12. 模块洞察区必须按业务域切换：合作方看生命周期，归因看来源与风险，资金看状态与金额，处理看优先级与SLA，报表看结论与国家表现，配置看版本与责任角色。
13. 配置中心首屏使用版本列表布局：暖白面板、浅色表头、高密度字段、状态文字标签和固定操作列；版本详情使用右侧抽屉，编辑/复制使用居中弹窗。
14. 系统配置使用独立表格页，不与业务版本表混排；系统参数保存后的反馈必须明确“不生成业务版本”。
13. 模块详情必须包含业务路径、对象360、来源系统、影响范围和依赖能力；路径步骤按业务域定义。

### 6c. 页面交互收口

全页面不再叠加统一“深度交互工作台”。该区域会复制页面既有的筛选、阶段看板、详情和任务入口，造成信息密度过高和操作干扰。

1. 生命周期相关页面才显示页面专属阶段看板，并与当前表格筛选同步。
2. 所有列表页保留统一筛选器、保存视图、排序、列设置和分页。
3. 详情、事件链、风险案件和报表下钻使用对应业务抽屉或弹窗，不使用通用对象检查器。
4. 高频动作放在表格行内；复杂动作放在业务弹窗中，并执行权限、原因和审计校验。
5. 业务路径、依赖系统和对象360只在相关详情抽屉展示，避免跨页面重复。

## 7. 表格

1. `table-layout:fixed`；字号12px。
2. 表头`#F8F6F1`、文字`#777269`、500、padding约`12px 14px`。
3. 数据行背景`#FFFDF9`，最小高49px，hover`#F8F4ED`。
4. 选择列固定左侧，操作列固定右侧；固定列保持背景和阴影。
5. 长文本省略并保留title或详情入口；数字右对齐。
6. 表尾左侧显示总数，右侧显示分页和每页条数。

## 8. 抽屉、弹窗与反馈

1. 复杂详情用右侧抽屉或全屏详情；轻确认用居中弹窗。
2. 抽屉底部操作固定；移动端按钮最小高44px。
3. 拒绝、冻结、解冻、配置生效、资金处置必须保留原因、权限和审计。
4. 全局消息用暖色白底面板，最大宽440px，可关闭。
5. Loading保留表头和面板高度；Empty显示“暂无数据”和下一步；Error显示错误码、原因、traceId和重试。

## 9. 可访问性与响应式

1. `:focus-visible`使用2px`--accent`。
2. 状态必须有文字，不只依赖颜色。
3. 触屏目标不低于44px；表格列宽热区在coarse pointer下加宽。
4. `prefers-reduced-motion: reduce`时压缩动画。
5. 1440、1279、390宽度必须检查无整页横向溢出、无文本重叠、无控制台错误。

## 10. Mock专属边界

1. 环境控制使用右下角浮动面板，默认收起；抽屉、弹窗和全局搜索打开时自动隐藏。
2. 页面呈现统一使用`Affiliate Admin API`、更新时间和业务口径，不显示“演示环境 / 虚构数据 / 演示数据”标注。
3. 静态Mock阶段仍使用本地逼真种子数据，不接入或写入生产客户数据；后续由同一数据源字段切换为Admin API响应。
4. 邮箱、手机号、证件、银行卡、设备指纹默认脱敏。
5. 参考站真实客户、资金、邮箱、手机号不得进入文档或Mock。
6. 搜索、通知、权限、审计属于横向能力，不新增第31个业务页签。
