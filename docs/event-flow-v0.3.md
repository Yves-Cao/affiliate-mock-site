# Affiliate × Max CRM × IMC 事件流转综合文档

版本：v0.3｜日期：2026-10-23｜用途：汇报与总结｜详细依据：接口文档设计稿 +《待决事项》CFD-D-011~014、Q-007

> v0.3 变更：同步2026-10-23 Q-007确认口径——佣金结算为日结且不设最低提现限制；Hold为动态机制（初始1天、按账户风险分递增，超过30天转冻结并进入人工审核）。v0.2已融入的CFD-D-011~014继续有效。

---

## 一、总览：三个系统在事件链路中的分工

| 系统 | 一句话定位 | 在事件链路中承担 |
| --- | --- | --- |
| **Max CRM** | 事实来源 | 用户注册、身份核验（KYC）、资金出入、交易成交——所有"钱和身份"的事实发生地；**推广链接体系的主场（CFD-D-012）** |
| **IMC** | 口径标准 | 埋点采集、事件命名与状态规范、统一分析口径——所有事件"怎么记、叫什么"的标准制定者 |
| **Affiliate** | 归因计佣 | 点击登记、归属判定、合规校验、佣金计提与结算——把上游事实翻译成"谁的客户、该给谁多少钱" |

核心逻辑一句话：**事实在 CRM 发生，口径按 IMC 标准，钱由 Affiliate 算**。

---

## 二、主链路：九段事件流转

```
合作方推广 → ①点击登记 → ②注册归因 → ③身份核验 → ④资金转化 → ⑤交易激活
                                                                    ↓
        数据沉淀⑨ ← ⑧风控介入 ← 佣金结算⑦ ← 达标判定⑥ ←──────────┘
```

### ① 触达与点击

| 项 | 内容 |
| --- | --- |
| 事件 | 客户点击合作方推广链接 |
| 流转 | 合作方端 → Affiliate（点击登记，接口组 IF-A） |
| 状态变化 | 产生匿名点击记录（未注册，仅匿名标识） |
| 业务规则 | 记录首次点击；30 天归因窗口从此起算 |
| 已确认口径 | 渠道边界：新方案只做 RevShare/CPA（合作方）数据，三方渠道功能保留不开发（CFD-D-011）；推广链接采用 CRM 推广链接数据格式，CRM 侧重构该功能以契合 UTM/RevShare/CPA（CFD-D-012） |

### ② 注册与归因锁定

| 项 | 内容 |
| --- | --- |
| 事件 | 客户在 CRM 完成注册 |
| 流转 | Max CRM → Affiliate（注册归因，接口组 IF-B） |
| 状态变化 | 匿名标识升级为正式用户；归属关系锁定 |
| 业务规则 | 首次点击优先；注册时点锁定归属且此后不改；无来源不归因；**身份互斥——只能归属 IB 推荐或 Affiliate CPA 推荐之一，以首触为准（CFD-D-014）** |
| 待评审建议 | 设备归因对接：`aff_device/add` 存量字段不动，走同标识匹配（CRM 零改造），兜底用 `identifier_1~10` 自定义位；真实必填集与设备档案关联时点联调前由研发澄清 |

### ③ 身份核验（KYC）

| 项 | 内容 |
| --- | --- |
| 事件 | 用户提交身份材料 → 审核通过 |
| 流转 | CRM 内部完成，结果回传 Affiliate |
| 状态变化 | 用户获得"已实名"身份；国家字段确定 |
| 业务规则 | 国家以 KYC 完成地址为准；KYC 用于同人去重，不改变已锁定归属 |

### ④ 资金转化（FTD）

| 项 | 内容 |
| --- | --- |
| 事件 | 首笔入金 → 实际到账（CRM 成功 FTD 事实）→ Affiliate 合规校验通过 → **有效 FTD** |
| 流转 | Max CRM → Affiliate（转化事实回传，接口组 IF-C） |
| 状态变化 | 用户从未付费 → 首付费 → 达标候选 |
| 业务规则 | 计佣口径只认"实际到账"，不认申请或支付成功；金额统一美元口径 |
| 已确认口径 | 有效 FTD 为复合判定：CRM 成功 FTD（判定标准出自 IMC 文档）× Affiliate 合规校验通过（标准出自 Affiliate 文档）；CRM 不为"有效性"单独落字段（CFD-D-013） |

### ⑤ 交易激活

| 项 | 内容 |
| --- | --- |
| 事件 | 真实账户开仓、平仓成交 |
| 流转 | 交易平台 → CRM → Affiliate（IF-C） |
| 状态变化 | 用户从"入金"到"真实交易" |
| 业务规则 | 达标条件=入金+交易组合，达标期限 30~90 天（数值待评审） |

### ⑥ 达标判定与佣金计提

| 项 | 内容 |
| --- | --- |
| 事件 | 有效 FTD + 交易行为满足 CPA 条件 |
| 流转 | Affiliate 内部判定 |
| 状态变化 | 佣金从"候选"进入"应计"，进入动态 Hold（初始1天，按账户风险分递增；超过30天转冻结并进入人工审核） |
| 业务规则 | Hold 期内发生拒付/退款 → 全额冲正，不足挂负；风险分递增映射待评审 |

### ⑦ 佣金结算

| 项 | 内容 |
| --- | --- |
| 事件 | 日度结算周期到达 |
| 流转 | Affiliate → Max CRM/财务（对账查询，接口组 IF-D） |
| 状态变化 | 应计 → 结算 → 可提现 |
| 业务规则 | 日结、不设最低提现限制；分国家档定价与动态Hold递增映射数值待评审 |

### ⑧ 风控介入（贯穿全程）

| 项 | 内容 |
| --- | --- |
| 事件 | 风险事件触发（虚假流量、撞库、设备集群、自荐等） |
| 流转 | Affiliate ↔ Max CRM（信号交换，接口组 IF-E） |
| 状态变化 | 正常流转 → 不归因 / Hold / 人工复核 / 申诉恢复 |
| 业务规则 | 硬门禁优先于评分；评分按事件权重累计账户风险分、分级施加限制（P1 建设）；全部处置留痕可申诉；自荐及亲属推广不允许（Q-014 部分确认） |

### ⑨ 数据沉淀与分析

| 项 | 内容 |
| --- | --- |
| 事件 | 上述各环节事件按统一口径上送 |
| 流转 | **两路上报**：①Affiliate → IMC（归因/佣金事件上送，接口组 IF-F，范围已收敛为 RevShare/CPA 数据）；②**Max CRM → IMC（CRM 业务数据上报）**——现状为 CDC 采集五类表，覆盖不全（无 KYC 历史、交易明细、IB 链路），需按 IMC 契约评估扩展上报范围 |
| 状态变化 | 业务事件 → 标准分析事件 |
| 业务规则 | 事件命名、状态枚举、去重规则全部遵循 IMC 事件契约；Affiliate 上送不作为计佣依据（计佣判定权在 Affiliate，CFD-D-011） |
| 资源提示 | CRM 侧数据上报扩展若立项，与推广链接重构（CFD-D-012）、设备归因改造（A-IF-02）同为 CRM 侧工作量，建议一并纳入估算 |

## 三、事件状态机（跨系统统一）

```
开始(started) → 提交(submitted) → 处理中(pending) ─┬→ 完成(completed) → 结算(settled)
                                                  ├→ 失败(failed)
                                                  └→ 拒绝(rejected)
完成/结算后 ──→ 冲正(reversed)   （拒付、退款、违规追索）
任意阶段 ──→ 取消(cancelled)
```

此状态机来自 IMC 事件契约，三系统共用；Affiliate 的佣金生命周期（候选→应计→Hold→可结算→已结算→已冲正）是其业务子集。

| --- | --- | --- | --- | --- | --- |
| 点击 | 推广链接点击 | 合作方端 | Affiliate | IF-A | P0 |

## 五、口径与缺口全景

### 5.1 已决口径

| 编号 | 口径 | 要点 |
| --- | --- | --- |
| CFD-D-011 | 渠道边界 | IMC 渠道数据方案属旧案；新方案只做 RevShare/CPA 数据；三方渠道功能保留不开发、留扩展空间；Affiliate 链接为合作方数据采集入口，计佣判定权在 Affiliate |
| CFD-D-012 | 链接格式 | 推广链接采用 CRM 现有推广链接数据格式，CRM 侧重构该功能以契合 UTM/RevShare/CPA；链接体系主场在 CRM；**CRM 侧新增一笔重构工作量，需纳入其资源估算与排期** |
| CFD-D-013 | 有效 FTD | 复合判定：CRM 成功 FTD × Affiliate 合规校验通过；FTD 判定标准出自 IMC 文档、合规标准出自 Affiliate 文档；CRM 不为"有效性"单独落字段 |
| CFD-D-014 | 身份互斥 | 用户只能归属 IB 推荐或 Affiliate CPA 推荐之一，不能同时转化，以首触为准；首触比较的技术口径（IB 触点取校验还是注册时点）待研发细化 |
| Q-007（2026-10-23） | 结算与Hold | 佣金日结且不设最低提现限制；Hold动态化：初始1天、按账户风险分递增，超过30天转冻结并进入人工审核；递增映射数值待评审 |

### 5.2 待决事项（三项，均已编号跟踪）

| 类别 | 缺口 | 影响 |
| --- | --- | --- |
| 架构选型 | CRM→Affiliate 事件回传方式（推送/轮询/CDC）未定 | 影响实时性与开发量 |
| 标准登记 | Affiliate 专属事件尚未在 IMC 事件契约登记（范围已收敛为 RevShare/CPA） | 上送 IF-F 的前置条件 |
| 基础设施 | 三系统间服务鉴权方案未定 | 所有接口联调的前置 |

另有联调前需研发澄清的实现细节：入金"实际到账"字段来源（A-IF-03）、`aff_device/add` 真实必填集与设备档案关联时点（A-IF-02）、首触比较技术口径（CFD-D-014 遗留）。

## 六、结论（汇报口径）

1. 事件流转主链路九段已全部理清，P0 段（点击→注册→KYC→入金→交易→计佣）业务口径全部确认闭环——当日评审连闭四项（CFD-D-011~014），无遗留口径争议。
2. 三系统分工清晰：CRM 出事实、IMC 定口径、Affiliate 管钱；无职责重叠。身份互斥与有效 FTD 复合判定进一步压实了边界：推荐身份与有效性判定权均在 Affiliate，CRM 只出事实。
3. 剩余工作集中在三项跨系统待决（回传方式、事件登记、鉴权），均已在 A-IF 编号体系下跟踪，不阻塞 P0 链路设计评审。
4. 上游依赖与资源提示：①IMC 两份契约 PRD 为草案未冻结，事件登记需走其治理流程，排期预留对接窗口；②CRM 侧工作量有三笔——推广链接功能重构（CFD-D-012）、设备归因改造（A-IF-02）、数据上报范围扩展（现状 CDC 仅五类表，⑨段），建议打包纳入 CRM 资源估算。
