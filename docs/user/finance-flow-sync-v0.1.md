# 用户端资金链路同步记录 v0.1

日期：2026-11-09  
范围：用户端 Mock 的收益、提现、保证金、结算单共享资金状态。

## 已同步的交互

- 提现申请提交后进入「待人工审核」。
- 审核通过后进入「支付中」；支付成功、失败或超时分别更新提现状态。
- 人工审核驳回、支付失败和支付超时均全额退回可提现余额，不产生手续费。
- 佣金状态与提现状态保持分离；收益、提现、保证金和结算单读取同一份本地资金状态。
- 一个提现单可以按先进先出分摊关联多个佣金和保证金流水。
- 结算单在提现提交时生成，每个提现单只对应一个结算单；结算单保存本次提现纳入的佣金和保证金明细快照。
- 每日自动结算与手动提现并存。模拟控制台可以按当前 Mock 日期运行一次凌晨自动结算，记录处理、阻断、失败数量、金额、时区、规则版本和 TraceId；自动结算只把符合条件的金额进入可提现余额，不创建提现订单，也不直接调用 CRM 打款。
- 提现审核通过后生成 CRM 打款请求，详情抽屉展示请求编号、打款编号、处理状态、状态说明、外部交易流水、请求/更新时间、重试次数和对账状态。

## 配置读取

保证金比例、正常释放天数、终止合作保留天数和结算冻结阈值统一读取 `AFF.finance.configuration`。页面只展示 Mock 演示参考值，不将这些数值写成生产承诺。

冻结演示记录带有客户、佣金案件、结算案件和风险信号的关联字段；用户端只展示有限状态、处理阶段和下一步，不展示内部评分或证据全文。

## API 适配边界

`api-adapter.js` 提供 Promise 形式的本地适配层，页面调用方式按未来 API 联调的异步形态组织。当前数据源仍为本地合成数据，`production: false`，不代表真实 HTTP 服务或外部支付、CRM、KYC/KYB 已接入。

## 状态边界

- `commissionStatus`、`settlementStatus`、`withdrawalStatus` 分开维护，CRM 回执只更新提现、分摊和余额，不覆盖佣金状态。
- Mock 的 CRM 打款仅为本地演示，支持处理中、成功、失败和退回；每个请求保留 `requestId`、`payoutId`、`externalTransactionId`、`statusReason`、`retryCount`、`reconciliationStatus` 等对接明细。
