# 完成合作者计划后的系统引导方案

版本：v0.1  
日期：2026-11-10  
状态：Draft，待用户确认后实施。本文属于用户端Mock与用户端页面设计输入，不定义新的生产业务规则。

## 1. 问题定义

当前合作者计划第5步“系统使用指引”只展示客户数据、业绩数据和仪表盘三个入口；第6步“分享简介链接”完成引导后，页面仅将按钮置为“已完成引导”并停留原页。合作者缺少一个从“我已了解计划”到“我知道如何开始投放、看数据、理解收益并完成提现准备”的连续任务流。

成熟系统的首登教育不应是百科式讲解，而应帮合作者在短时间内完成三件事：

1. 产生第一次有效投放动作：选定市场、复制正确链接、拿到素材。
2. 建立数据反馈预期：知道点击、注册、FTD、有效FTD、质量服务和佣金在哪里看。
3. 建立资金预期：知道佣金何时结算、保证金何时释放、提现前还缺什么资料。

## 2. 当前缺口

| 编号 | 缺口 | 当前表现 | 影响 |
|---|---|---|---|
| OB-G01 | 无完成后的统一行动清单 | 第6步完成后停留在原页 | 合作者不知道下一步优先做什么 |
| OB-G02 | 引导偏阅读，缺少动手任务 | 第5步是三张入口卡，不记录用户是否完成过关键动作 | 看过不等于会用 |
| OB-G03 | 缺少转化与佣金时间线 | 分散在合作者计划、客户、收益和保证金页面 | 新合作方难以建立“客户动作到佣金入账”的整体预期 |
| OB-G04 | 缺少渠道场景化路径 | 未区分自然流量、付费投放、内容站、社群、代理机构 | 不同合作方需要的第一步不同 |
| OB-G05 | 素材接受准则未纳入系统引导 | 素材准则只在素材库首次打开时出现 | 合作者可能拿到链接后才被素材门槛打断 |
| OB-G06 | 回传配置缺少新手判断 | 仪表盘展示平台入口，但不引导“谁需要配置、何时配置” | 非专业合作方被追踪器概念干扰，专业合作方又不知道能力边界 |
| OB-G07 | 数据解读缺少行动建议 | 报表可筛选和下钻，但新手不知道低转化时先看什么 | 数据可见不等于能优化 |
| OB-G08 | 提现前置资料缺少渐进提醒 | KYC/KYB和收款税务信息集中在提现时暴露 | 合作者在有可提现金额时才发现资料缺失，体验差 |
| OB-G09 | 空数据首登体验未区分 | 当前Mock充满演示数据，生产新账户初期可能无数据 | 新合作方无法判断系统是否正常工作 |
| OB-G10 | 缺少可返回的新手中心 | 完成计划后没有统一入口回看引导 | 用户忘记概念后只能求助工单 |

## 3. 推荐方案：三层渐进引导

### 3.1 第一层：完成页“开始推广检查清单”

触发：点击“完成引导”后。

页面：不新增路由，直接在`apply`第6步下方或成功态面板展示，并提供“进入仪表盘继续准备”按钮。

清单分为四组：

| 分组 | 任务 | 完成依据 | 下一步入口 |
|---|---|---|---|
| 开始投放 | 选择主要推广国家 | 用户在计划第2步选择过国家，或后续在仪表盘选择 | `apply`第2步 |
| 开始投放 | 复制网页/移动推广链接 | 复制事件已发生 | `dash`推广链接卡 |
| 开始投放 | 阅读并接受素材准则 | `assetsAccepted=true` | `assets` |
| 开始投放 | 下载或复制一个素材 | 素材下载/复制事件 | `assets` |
| 理解收益 | 查看转化与佣金时间线 | 引导页一次 | `apply`说明区或帮助中心 |
| 理解收益 | 查看客户数据字段 | 进入过`clients`并打开过详情 | `clients` |
| 理解收益 | 查看收益与保证金说明 | 进入过`pay`或`guarantee` | `pay` |
| 提现准备 | 完成基础资料与KYC/KYB | 复用`onboarding`状态 | `onboarding` |
| 提现准备 | 确认收款与税务资料 | 个人中心财务税务状态 | `account` |
| 可选追踪 | 配置回传 | `tracker`已有启用配置；自然流量可标记暂不需要 | `tracker` |

展示规则：

1. 默认展示前6项，其余折叠为“查看全部准备项”。
2. 每项显示完成/未完成，不给惩罚性红色；未完成用中性蓝色。
3. “暂不需要”仅允许出现在回传配置等可选项。
4. 清单完成度不阻塞链接使用，只作为新手引导。
5. 清单可从仪表盘“继续准备”入口再次进入。

### 3.2 第二层：仪表盘“继续准备”卡片

位置：仪表盘“使用建议”区域升级为“推广准备”区域，或并列新增一张紧凑卡片。

状态：

| 状态 | 展示 | 主按钮 |
|---|---|---|
| 未完成核心项 | “完成X项，开始你的首次投放” | 继续准备 |
| 核心项完成 | “基础推广已准备好” | 查看建议 |
| 有首批点击 | “首批点击已到达，查看转化情况” | 查看客户数据 |
| 有首批注册/FTD | “首批客户已转化，查看佣金路径” | 查看收益数据 |
| 可提现前资料缺失 | “完成资料，避免影响首次提现” | 去完善资料 |

核心项建议：选择国家、复制链接、接受素材准则、获取素材、查看资金时间线。KYC/KYB和收款税务资料作为提醒项，不与投放核心项混在同一进度分母。

### 3.3 第三层：系统导览抽屉

入口：

1. 完成合作者计划后的成功面板。
2. 仪表盘“继续准备”。
3. 帮助与工单中心的“系统导览”。

导览分8步，每步一屏，避免长文：

| 步骤 | 标题 | 内容 | 动作 |
|---|---|---|---|
| 1 | 你的推广链路 | 点击、注册、FTD、有效FTD、质量服务到佣金的路径图 | 查看客户数据 |
| 2 | 选择市场 | 支持地区、端平台、语言与高转化地区 | 打开支持地区 |
| 3 | 获取链接 | 普通链接、深度链接、活动与Sub ID的适用场景 | 复制推广链接 |
| 4 | 获取素材 | 类型、语言、尺寸、平台与合规准则 | 前往素材库 |
| 5 | 看懂数据 | 点击率、注册率、FTD率、有效FTD率分别说明什么 | 进入业绩数据 |
| 6 | 理解收益 | 佣金、税费、保证金、结算中、可提现的简化时间线 | 进入收益数据 |
| 7 | 准备提现 | KYC/KYB、收款账户、税务资料与提现状态 | 前往个人中心 |
| 8 | 需要帮助时 | 工单、申诉、消息与回传排查入口 | 打开帮助中心 |

导览要求：

1. 支持“上一步/下一步”和Escape关闭。
2. 记录已读步骤，但不过度弹窗。
3. 每步提供真实路由跳转，跳转后可返回继续。
4. 移动端全宽抽屉，不做遮罩下滚动锁死。
5. 中文和英文同步。

## 4. 关键内容设计

### 4.1 转化与佣金时间线

建议用一条横向时间线解释：

```text
有效点击
→ 客户注册并完成KYC
→ FTD
→ 有效FTD确认资格档
→ 生成基础CPA佣金
→ 动态结算与结算前检查
→ 扣除税费与保证金
→ 进入可提现余额
→ 质量服务附加佣金另行计算
→ 手动提现
```

页面文案建议：

“佣金不是在客户首次入金时立即到账。系统会先确认FTD和有效FTD，再按国家与资格档计算佣金；结算前会完成风险、税费和保证金检查。你可以在客户数据中查看每个阶段，在收益数据中查看每笔佣金的当前状态。”

### 4.2 新手数据看板解释

在每个指标旁增加轻量说明：

| 指标 | 新手解释 | 低表现时的下一步 |
|---|---|---|
| 点击量 | 链接被访问的次数 | 检查投放渠道、素材和落地页匹配度 |
| 注册客户 | 通过链接完成注册的去重客户 | 检查目标市场、语言和注册页选择 |
| FTD客户 | 完成首次入金的客户 | 查看客户KYC与入金前流失阶段 |
| 有效FTD | 达到交易条件并确认资格档的客户 | 查看资格档条件和交易活跃情况 |
| 质量服务 | 满足质量服务的客户 | 查看交易活跃与风险状态 |

### 4.3 渠道场景路径

| 合作方类型 | 首选路径 | 建议默认任务 |
|---|---|---|
| 社群/自然流量 | 链接、GIF、短视频、支持地区 | 复制移动链接，获取本地语言素材 |
| 内容站/SEO | 横幅、落地页、深度链接 | 配置目标页和语言，嵌入a标签 |
| 付费投放 | 活动、二级渠道、回传、报表分组 | 创建活动与Sub ID，配置回传 |
| 代理机构 | 二级渠道、报表导出、API需求登记 | 按渠道拆分Sub ID，定期查看冲正与质量 |

首版可在系统导览开始时询问一次“主要推广方式”，再高亮对应路径；不强制注册时填写。

## 5. 实现方案

### 5.1 Mock第一版：不新增路由

改动点：

1. `complete-program`后不再仅停留在原按钮状态，展示“引导已完成，继续准备”成功面板。
2. 在`AFF.state`增加`postProgramGuide`：
   - `started`
   - `finishedSteps`
   - `dismissed`
   - `channel`
   - `trackerNotNeeded`
3. 根据既有状态推导任务：
   - 推广链接复制：可先用本地状态记录。
   - 素材准则：`state.assetsAccepted`。
   - KYC/KYB：`state.onboarding.kycCompleted`。
   - 资料提交：`state.onboarding.submitted`。
   - 回传：存在启用配置或标记暂不需要。
4. 仪表盘新增“推广准备”卡片，点击打开右侧导览抽屉。
5. 帮助中心增加“系统导览”入口。

验收：

1. 完成合作者计划后能看到成功面板和前6项任务。
2. 点击任务能进入正确页面。
3. 复制链接、接受素材准则、完成KYC后，清单状态自动更新。
4. 清单不阻塞推广链接使用。
5. 刷新后进度保留。
6. 中英文一致，移动端不溢出。

### 5.2 Mock第二版：事件化与数据空态

1. 将导览步骤读取和完成写入`localStorage`。
2. 增加“新合作者空态”场景：
   - 无点击、无客户、无佣金时展示时间线说明。
   - 数据卡片显示“等待首批点击”，不用假成功。
3. 增加首批事件通知：
   - 首次点击到达。
   - 首个注册客户。
   - 首个FTD。
   - 首笔佣金生成。
   - 首次可提现。
4. 消息中心提供“新手引导”分类。

### 5.3 生产化要求

1. 服务端维护`PartnerOnboardingGuide`状态，不以纯前端状态作为最终事实。
2. 任务完成依据服务端事件或审计动作，不由客户端自行伪造。
3. 任务状态区分：
   - `not_started`
   - `in_progress`
   - `completed`
   - `not_required`
   - `blocked`
4. 权限与审计：
   - 查看、开始、完成、跳过均记录审计。
   - KYC/KYB、收款、税务资料以CRM或账户服务事实源为准。
5. API建议：
   - `GET /partner/onboarding-guide`
   - `PATCH /partner/onboarding-guide/{task_id}`
   - `POST /partner/onboarding-guide:dismiss`
6. 通知与任务状态联动，但不因未完成引导阻塞链接、计佣或提现资格。
7. 帮助中心和消息中心可回放导览。

## 6. 不建议的做法

1. 不做强制全屏教程：会放大入驻摩擦。
2. 不把21个页面逐一介绍：合作者只需要第一层任务路径。
3. 不用内部状态机和风控术语做首登解释。
4. 不把“完成引导”作为链接可用门禁：教育任务与业务资格分离。
5. 不用纯静态文案代替状态推导：任务必须根据真实动作自动变化。

## 7. 建议实施顺序

1. P0：完成合作者计划后的成功面板与核心6项清单。
2. P0：转化与佣金时间线说明。
3. P0：仪表盘“推广准备”卡片。
4. P1：8步系统导览抽屉。
5. P1：帮助中心新手入口。
6. P1：新合作者空态和首批事件通知。
7. P2：渠道类型个性化路径。
8. P2：服务端任务状态、API和审计。
